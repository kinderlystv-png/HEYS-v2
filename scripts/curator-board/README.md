# Доска куратора — локальная сводка дня по клиентам

Одна страница на `localhost`: по каждому активному клиенту видно, что он внёс
сегодня — приёмы пищи, воду, шаги, тренировку, вес, сон — и что не внёс.
Обновляется сама раз в минуту, пока запущен процесс.

```bash
node scripts/curator-board/server.mjs
```

→ http://localhost:4777

## Что это и чем не является

Это **локальный операционный инструмент куратора**, а не часть продукта. Он
живёт вне приложения, ничего не пишет и не деплоится. Читает тем же путём, что
PWA и `heys-mcp`: curator JWT → REST `client_kv_store` (`heys_dayv2_<дата>` и
`heys_profile`).

В приложении та же сводка есть на карточке клиента в кураторском gate — через
`get_curator_clients_day_summary`
([CURATOR_WORKSPACE.md](../../docs/reference/systems/CURATOR_WORKSPACE.md)).
Доска остаётся для случаев, когда удобнее отдельная страница: она показывает
больше метрик и историю за 7 дней, не занимая места на карточке.

## Доступ

Креды берутся из `.env.local` (в git не попадает):

| Переменная                                             | Назначение                            |
| ------------------------------------------------------ | ------------------------------------- |
| `HEYS_CURATOR_EMAIL` / `HEYS_TEST_CURATOR_EMAIL`       | email куратора для `POST /auth/login` |
| `HEYS_CURATOR_PASSWORD` / `HEYS_TEST_CURATOR_PASSWORD` | пароль                                |

JWT держится в памяти процесса до истечения `expires_in`, на диск не пишется.

Сервер слушает только `127.0.0.1`. У `/api/summary` нет авторизации, а отдаёт он
данные о здоровье реальных людей — с открытым портом сводку забрал бы любой в
той же сети. Если понадобится смотреть доску с телефона, правильный путь не bind
на все интерфейсы, а токен на эндпоинте.

## Настройки

| Переменная           | По умолчанию             | Что делает                                         |
| -------------------- | ------------------------ | -------------------------------------------------- |
| `HEYS_BOARD_PORT`    | `4777`                   | порт страницы                                      |
| `HEYS_BOARD_API`     | `https://api.heyslab.ru` | адрес API                                          |
| `HEYS_BOARD_CLIENTS` | —                        | явный список имён через запятую вместо автофильтра |

По умолчанию показываются клиенты со статусом `active`, кроме технических
(`E2E-*`, `HEYS production smoke *`, `тестовый *`).

## Что на карточке

Первый слой — шесть строк за сегодня с явным «нет / не вбиты / не введён» и
полоска заполненности за 7 дней. Второй слой (`Подробнее`) — состав приёмов,
БЖУ, бытовая активность, качество сна, настроение, время последней отметки воды.

День берётся по московскому времени — тот же «сегодня», что видит клиент.
