Снапшот: актуализирован 2026-07-31; дополнен после полного release-readiness
аудита
[`docs/release-readiness-methodology.md`](../docs/release-readiness-methodology.md).
Источники: ревью корпуса `маркетинг/` (01–21 + xlsx), утренний бриф 2026-06-10,
методология Pro-first (зафиксирована 2026-06-09, коммит `d7b8b039`), локальный
аудит кода/документов 2026-06-14 и 10-прогонный аудит проекта 2026-06-17.

**Главный вывод ревью:** юридический и security-контур R0 закрыт: запись РКН
опубликована, пользовательские документы синхронизированы, ИСПДн/security-smoke
пройдены. Live-smoke Telegram 2026-07-28 выявил техническую регрессию приёма
контакта и повторные ответы на один update; fix опубликован в тот же день.
Повторный личный smoke подтвердил один ответ бота, одну сохранённую заявку, один
PII-free handoff без дублей и успешный операторский claim с обновлением
карточки. Telegram contact-smoke и текущий landing baseline зелёные: повторная
заявка с тем же контролируемым номером вернула success и была ожидаемо
дедуплицирована без второй карточки. Production intake-path теперь подтверждён
целиком: claim → защищённая анкета → разбор и корректировка ответа куратором →
ручное одобрение → создание одного клиента и выдача нового PIN. В новом
review-flow доступны только два финальных решения: одобрить или отказать. Первый
вход по только что выданному PIN также работает: показаны и приняты обязательные
согласия, все оставшиеся шаги регистрации сохранены, после чего клиент увидел
fail-closed экран «Аккаунт готов». В curator UI созданный клиент отображается со
статусом «Нет подписки», без автоматического запуска пробной недели. Ранний
`profile_sync_timeout` оказался временным следствием прогрева PostgreSQL после
разблокировки Yandex Cloud: после перехода базы в `RUNNING` авторизованные
`client_kv_store`-запросы прошли, ошибка не повторилась. Следующий ручной gate —
активация триала уже подтверждена: curator UI показал `trial` и дату окончания.
Post-activation smoke выявил новый blocker: вместо чекина снова открывается
регистрационный мастер, хотя cloud-профиль имеет `profileCompleted=true`.
Подтверждённая причина — остаточный глобальный `heys_registration_in_progress`
имеет приоритет над завершённым профилем. Локальный fix готов: stale marker
снимается только после полного sync того же клиента, не старее
`profile.updatedAt`; более свежий локальный профиль остаётся fail-closed.
Combined scoped deploy выполнен в оба PWA-бакета, CDN очищен; isolated
production boot подтвердил все новые hashes, HTTP 200, console errors 0 и оба
regression-branch прямо в опубликованном bundle. Ручной authenticated PIN-smoke
2026-07-31 подтвердил: welcome показан один раз; регистрационный мастер и
profile-steps повторно не появились; утренний чекин завершился событиями
`flow_complete` и `flow_cloud_synced`; дневник, nutrition-карточки и обучающая
plate-модалка открываются. Registration blocker закрыт. Подтверждённые
post-activation дефекты исправлены локально 2026-07-31 без изменения
registration/profile-resume: active trial не создаёт header/banner/CTA, краткий
срок остаётся в выпадающих настройках, подробности — в блоке «Подписка»;
`read_only` использует отдельный gate с контактом куратора. StepModal сохраняет
внешние шаги при повторной lazy-загрузке и пишет privacy-safe build/SW
diagnostic при timeout; ожидаемый отказ orientation lock больше не считается
incident. Для `heys-api-messages` identity lookup переведён на
healthy-client/retry и контролируемый credentialed CORS для 5xx. Isolated local
preview 390×844 подтвердил свободную шапку, рабочий `payment_required`, API 200
и console errors/warnings 0. Это ещё не production evidence: deploy и повторный
authenticated production smoke требуют отдельного разрешения. До первой оплаты
отдельно закрывается R1, до платного масштабирования — R2.
