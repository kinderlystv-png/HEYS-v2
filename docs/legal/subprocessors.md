# Подпроцессоры (subprocessors) — HEYS

**Действует с:** 2026-07-27 **Версия:** 1.2 **Сверено с кодом и облаком:**
2026-08-11 (§ 4 — SMS-провайдер; остальные разделы сверку этого дня не
проходили)

Список третьих лиц, которым HEYS передаёт персональные данные пользователей для
оказания услуг сервиса. Согласно 152-ФЗ ст.6 и GDPR Art.28.

## 1. Yandex.Cloud (LLC «Яндекс.Облако», Россия)

**Что обрабатывает:**

- PostgreSQL Managed Service: всю БД клиентов (профиль, дневник, согласия,
  подписки).
- Object Storage (S3-совместимый): резервные копии, статические ассеты,
  фотографии и голосовые сообщения внутреннего чата.
- Cloud Functions: серверные API-обработчики (heys-api-rpc, heys-api-auth,
  heys-api-payments, heys-api-leads, heys-bot-client, heys-cron-\*).
- Lockbox: секреты (пароль БД, токены ботов).
- CDN: доставка статики лендинга/PWA.

**Регион:** Россия (ru-central1). **Юр.основание:** ст.18.5 152-ФЗ (хранение ПДн
россиян в РФ). **Контракт:** публичный договор оферты Yandex.Cloud.

## 2. ЮMoney / ЮKassa (НКО «ЮMoney», Россия)

**Что обрабатывает:**

- Платёжные транзакции (имя, телефон, email клиента, сумма, план).
- Возвраты средств.
- 54-ФЗ чеки (электронная касса).

**Регион:** Россия. **Юр.основание:** 54-ФЗ + договор с НКО. **Карточные
данные** обрабатываются на стороне ЮKassa (PCI DSS), HEYS их не хранит.

## 3. Telegram (Telegram Messenger Inc., США/Великобритания)

**Что передаётся:**

- **Через бота-куратора** (`TELEGRAM_CLIENT_BOT_TOKEN`): сообщения от клиента к
  куратору и обратно. Содержание — то что пользователь добровольно отправил.
- **Через бота-уведомлений** (`TELEGRAM_BOT_TOKEN`): аггрегаты по
  лидам/security-alerts (без PII в основном payload; UUID-prefix вместо имени).

**Юр.основание:** пользователь явно согласился использовать Telegram как канал
коммуникации (выбор messenger в TrialForm). **Caveat:** Telegram-сервера могут
находиться вне РФ — при выборе Telegram как канала пользователь информируется
(privacy-policy.md §10).

## 4. SMS-провайдер — SMS.ru (проверено 2026-08-11)

**Что обрабатывал бы:** номер телефона клиента и текст сообщения с одноразовым
кодом. Назначение — простая электронная подпись согласий: код из SMS вместо
галочки.

**Статус: передачи нет, канал выключен.** Согласия по-прежнему фиксируются через
checkbox и аудит-лог (IP, User-Agent, версия документа, хэш текста). Отправку
гейтит флаг `SMS_VERIFICATION_ENABLED = false` в `apps/web/heys_consents_v1.js`:
при выключенном флаге клиент не вызывает отправку кода вовсе.

**Важное уточнение к прежней редакции.** До 2026-08-11 здесь стояло «функция
`heys-api-sms` удалена 2026-05-22» — на момент написания это было верно. Сегодня
функция снова активна в облаке: правка CORS затронула шесть функций разом
(коммит `d5813e31b`), и `heys-api-sms` задеплоилась вместе с группой. Её
единственная версия создана 2026-08-11 08:24 UTC, то есть между 22 мая и этой
датой функции в облаке не существовало и сообщения уходить не могли. Это пример
того, как внешний обработчик возвращается в прод побочным эффектом косметической
правки, не появившись ни в одном юридическом документе.

**Что требуется до включения ПЭП** (порядок обязателен):

1. Договор поручения обработки с провайдером — сейчас его нет, и он не был
   нужен, поскольку передачи не происходило.
2. Строка о провайдере в `privacy-policy` — вносится вместе с включением, не
   раньше: политика описывает фактическую обработку, и запись о передаче,
   которой нет, — такой же дефект, как умолчание о той, которая есть.
3. Обновлённые тексты `user-agreement` и `health-data-consent`, где код из SMS
   описан как применяемый метод подписи.
4. Внешнее юридическое заключение о достаточности этой модели ПЭП для
   письменного согласия по специальной категории (оговорка стоит в коде,
   `heys_consents_v1.js`).

Пока пункты не закрыты, флаг не включать. Если решение о ПЭП будет отложено
надолго, чище убрать функцию из облака обратно: задеплоенный, но неиспользуемый
обработчик с доступом к Lockbox — лишняя поверхность и источник ровно того
расхождения, которое описано выше.

## 5. Аналитика

- **Yandex.Metrika** (ООО «Яндекс», Россия) — статистика посещений лендинга
  только после отдельного выбора «Разрешить». До opt-in скрипт и `noscript`
  fallback не загружаются. Webvisor выключен; отказ не мешает заявке.
- **Google Analytics 4** — **удалён** 2026-05-20 (раньше был под env-флагом,
  трансграничная мина).
- **Meta Pixel** — **удалён** 2026-05-20 (та же причина).
- **Sentry / Mixpanel / другая трекинг-аналитика** — отсутствует.

## 6. Расшифровка речи

- **Yandex SpeechKit** (инфраструктура Яндекса, Россия) — выбранное голосовое
  сообщение и технический идентификатор задания для автоматической расшифровки.
  Передача выполняется только при действующем отдельном согласии
  `speech_transcription` версии 1.1; старая версия не принимается. Голосовое
  может содержать health-data, поэтому без действующего `health_data` обработка
  должна блокироваться.
- OpenAI, Anthropic и иные генеративные AI-API для клиентских ПДн не
  используются.

## Уведомление при изменении

Если добавляется новый подпроцессор:

1. Обновить этот документ.
2. Если новый подпроцессор обрабатывает PII вне РФ — bump версии `privacyPolicy`
   в
   [apps/landing/src/config/legal-versions.ts](../../apps/landing/src/config/legal-versions.ts)
   → запустится re-consent flow для всех активных клиентов (см.
   `check_required_consents_v2` + `ConsentOutdatedBanner`).
3. При трансграничной передаче — уведомление РКН (ст.12 152-ФЗ).
