# E. Разграничение прав доступа и журнал обращений

**Для юриста · HEYS · сверка 11.08.2026**

## Вопрос

Есть ли сейчас разграничение прав доступа сотрудников к персональным данным и
ведётся ли журнал обращений к данным?

## Ответ

**Нет — в том виде, который нужен как организационно-техническая мера при работе
с ПДн и при найме кураторов.**

Ниже — уточнение, чтобы ответ не выглядел как «в коде нет ни одной строки».

### Разграничение прав

| Что есть                                                                                                 | Чего нет                                                                                                                    |
| -------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Клиент видит только свои данные через свою сессию                                                        | Ролей сотрудников с разным объёмом доступа (оператор / куратор / поддержка / разработчик) как рабочего контура              |
| Назначение куратора на клиента (`curator_id`) и отказ «куратор не владеет клиентом» на части write-путей | Штатного разграничения: сейчас куратор один — сам оператор                                                                  |
|                                                                                                          | Подключение к БД приложения идёт под административной ролью; точечные гранты «на бумаге» не являются фактическим периметром |
|                                                                                                          | Приказа о допущенных лицах, перечня доступов и обязательств для наёмных кураторов — в треке «при найме», не внедрено        |

Итого: техническая привязка «свой клиент» для одного владельца есть;
**разграничения прав как меры при нескольких допущенных лицах — нет.**

### Журнал обращений к данным

| Что есть                                                                                       | Чего нет                                                                                                                                                            |
| ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Таблица `data_access_audit_log` и функция `log_data_access`                                    | Журнала, который можно предъявить как полный учёт «кто когда смотрел дневник / переписку / анкету»                                                                  |
| Частичная запись при части curator RPC (fire-and-forget после некоторых вызовов с `client_id`) | Покрытия всех чтений: списки и агрегаты намеренно пропускаются; путь панели/REST/мессенджера не равен полному аудиту                                                |
| Политика конфиденциальности **заявляет** журналирование доступа                                | Соответствия факту: в плане релиза на 11.08 зафиксировано — «журналирование доступа: заявлено, отсутствует» / «аудит чтений куратором — сейчас не логируется вовсе» |

Итого для юриста одной фразой: **журнал обращений как заявленная мера сейчас не
ведётся.**

### Зачем это в пакете

При найме кураторов без разграничения прав и журнала нельзя честно закрыть
обязанности оператора по доступу. Пока ведёт один человек (оператор), риск иной,
но формулировка для документов и для найма должна оставаться: **меры не
внедрены.**
