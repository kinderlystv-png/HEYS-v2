## 1. Зачем строка нужна

Кураторское push-уведомление содержит имя клиента — так устроено согласие
куратора 1.1: «Текст уведомления может содержать имя клиента и краткое описание
события».

Согласия куратора для этого недостаточно: оно про данные куратора и про его
устройство. Обработка имени клиента требует основания со стороны клиента.
Основание есть — согласие на доступ куратора разрешает просматривать профиль,
дневник и переписку, а уведомление это форма того же доступа, вынесенная на
экран устройства куратора.

**Но связь эта выводится, а не написана.** Строка ниже её проговаривает.

```
> **Версия:** 1.2<br> **Дата вступления в силу:** __ ______ 2026 г.<br>
> **Последнее обновление:** __ ______ 2026 г.

**Оператор:** ИП Поплавский Антон Сергеевич, ИНН 263517141102, ОГРНИП
320265100094118, адрес: 355041, г. Ставрополь, ул. Краснофлотская, д. 88/1, кв.
56, email: poplanton@mail.ru.

Я разрешаю назначенному HEYS куратору просматривать данные моего профиля,
дневника и переписки в объёме, необходимом для сопровождения.

Уведомления о событиях по моему дневнику могут направляться на устройство
куратора и содержать моё имя. Куратор обязан не допускать просмотра таких
уведомлений третьими лицами.

Куратор — физическое лицо, которому Оператор поручил ведение моего дневника.
Сейчас сопровождение ведёт сам Оператор. Актуальный перечень допущенных
кураторов можно получить по запросу на poplanton@mail.ru. Каждый куратор связан
обязательством о неразглашении.

Доступ можно отозвать в настройках; после отзыва сопровождение куратором
прекращается.
```

**Дата вступления в силу оставлена пустой намеренно.** По решению юриста от
20.08 документ не может вступить в силу раньше, чем стал доступен для
подписания: дата ставится по факту регистрации версии, а не по дате вычитки.

**Второе предложение абзаца — сверх того, что просил юрист.** Он диктовал одну
строку, про обязанность куратора речи не было. Добавлено потому, что обязанность
уже существует в согласии куратора 1.1 («не допускать просмотра таких
уведомлений третьими лицами… доступ к которому защищён»), то есть нового
обязательства не создаёт, а согласие клиента делает информированным: клиент
видит не только что имя уйдёт на чужой экран, но и чем это ограничено. **Если
юрист сочтёт лишним — вычёркивается без последствий для остального текста.**

## 3. Что Mozilla здесь не появляется

Решением владельца от 20.08 Mozilla не подключается: Firefox — меньше двух
процентов пользователей, и три версии документов с переподписанием под канал,
которым никто не пользуется, не окупаются. Она остаётся названной только в
уведомлении РКН № 100383874 — заявить регулятору больше, чем используешь,
безопасно.

Держится это на белом списке хостов доставки
([`push-endpoint-host.js`](../../yandex-cloud-functions/heys-api-push/push-endpoint-host.js)):
пока там только `fcm.googleapis.com` и `web.push.apple.com`, документы верны.
Условие записано в шапке самого файла.

## 4. Чек-лист выпуска

Версия трогает шесть мест. Половинчатый выпуск роняет канарейку
`check-live-legal-drift.mjs`, поэтому либо всё, либо ничего.

| #   | Что                                                                                                |
| --- | -------------------------------------------------------------------------------------------------- |
| 1   | `docs/legal/curator-access-consent.md` — текст из раздела 2, дата по факту регистрации             |
| 2   | `docs/legal/_pack-1.11-ascii/12-curator-access-consent-1.1.md` — переименовать в `-1.2` и обновить |
| 3   | `apps/web/public/docs/v1.2/curator-access-consent.md` — снимок новой версии                        |
| 4   | `docs/legal/legal-document-manifest.json` — `version`, `snapshotPath`, пересчитанный `sha256`      |
| 5   | `apps/web/heys_legal_versions_v1.js` — `curator_access: '1.1'` → `'1.2'`                           |
| 6   | миграция регистрации по образцу `database/2026-08-14_activate_legal_v1_11.sql`                     |

Страницы на лендинге у этого документа нет — канарейка сверяет посадочные
страницы только для `user_agreement` и `personal_data`, так что здесь правки не
требуется.

Форма строки в миграции:

```sql
('curator_access', '1.2', '<sha256 снимка>',
 'apps/web/public/docs/v1.2/curator-access-consent.md', 'active', '<дата>')
```

Плюс блок деактивации предыдущей версии — в образце это условие вида
`consent_type = 'curator_access' AND document_version <> '1.1'`, номер меняется
на `'1.2'`.

**Переподписание:** пять аккаунтов, вместе с пакетом 1.11. Версия 1.1 не
аннулируется и остаётся в архиве снимком текста, под которым есть подпись, — по
тому же решению юриста, что и для кураторской 1.0.
