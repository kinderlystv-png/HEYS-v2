## Коротко

Первичная запись клиентских данных происходит в российской базе и российском
объектном хранилище. Куратор видит то же, что лежит у клиента в дневнике и
переписке. **Передачи клиентских персональных данных за границу нет.**
Уведомление в Роскомнадзор о трансграничной передаче не подаётся.

Функция `heys-mcp` 11.08.2026 была снята из прода (чтобы не вести клиентские ПДн
через внешние LLM), затем **в тот же день возвращена** осознанным деплоем как
кураторский инструмент Cursor/задачник (`d4epjmd9lnk059u29bg8`). Автодеплой
по-прежнему выключен. Это не открытие продуктового канала «клиент → зарубежная
модель»: кураторский коннектор ходит в тот же российский API, что и приложение.

Резервные копии — только на стороне Yandex Cloud в РФ (см. документ F).

## Пять каналов

### 1. Сообщение (текст в чате с куратором)

1. Клиент пишет текст в приложении.
2. Сообщение сразу сохраняется в базе HEYS (переписка клиента).
3. Куратор читает его в панели / мессенджере приложения.
4. Во внешние сервисы текст **не уходит**, кроме случая, когда клиент сам выбрал
   Telegram как канал связи — тогда сообщение идёт через Telegram (это отдельный
   канал связи по выбору клиента, не «выгрузка базы»).
5. В резервные копии попадает вместе с остальной базой / суточными снимками.

### 2. Фото

1. Клиент прикрепляет фото (еда, этикетка и т.п.).
2. Файл сохраняется в объектном хранилище Yandex (бакет фото) в РФ; в переписке
   остаётся ссылка/путь.
3. Куратор открывает фото через авторизованное чтение в приложении.
4. Во внешние AI/зарубежные сервисы фото **не передаётся**. Распознавание
   «машиной» для клиентов не включено.
5. Фото попадает в объектное хранилище и в общие бэкапы инфраструктуры;
   orphan-файлы после удаления клиента чистятся отдельным заданием (срок grace —
   см. F / политику retention).

### 3. Голосовое

1. Клиент записывает голосовое в чате.
2. Аудиофайл сохраняется в том же российском объектном хранилище; запись о
   сообщении — в базе.
3. **Если** у клиента есть отдельное согласие на расшифровку речи — выбранное
   голосовое уходит в **Yandex SpeechKit** (Россия) для автоматической
   расшифровки; текст расшифровки возвращается в сервис.
4. Без этого согласия расшифровка не запускается. Зарубежным AI голосовое не
   передаётся.
5. Куратор видит аудио и (при наличии) текст расшифровки в переписке.
6. В бэкапы — как файл и как запись в базе.

### 4. Чек-ин (утро)

1. Клиент заполняет утренний чек-ин в приложении (вес, сон, оценки самочувствия
   и т.д.).
2. Значения сразу пишутся в дневник дня клиента в российской базе.
3. Во внешние сервисы чек-ин **не уходит**.
4. Куратор видит те же поля в дневнике клиента.
5. В бэкапы — вместе с дневником.

### 5. Внесение куратором

1. Клиент прислал сообщение / фото / голосовое **или** куратор получил данные
   иным согласованным способом.
2. Куратор вручную вносит приём пищи, воду, правку дня и т.п. в дневник через
   панель приложения (или через свой рабочий контур на двух семейных аккаунтах).
3. Запись сохраняется в той же российской базе, что и при самозаписи клиента.
4. Чужие клиентские данные в зарубежную модель / внешний LLM **не передаются**.
5. Куратор видит результат своей же записи в дневнике клиента.
6. В бэкапы — как обычные данные дневника.

## Что видит куратор

Куратор, назначенный клиенту, видит: профиль, дневник (еда, вода, сон,
активность, самочувствие), переписку, фото и голосовые этого клиента,
предтриальную анкету (если есть), статусы подписки и согласий в объёме, нужном
для ведения. Чужих клиентов без назначения система не отдаёт списком «всех
подряд» — фильтрация по назначению есть. На практике сейчас куратор один (сам
оператор).

## Внешние получатели (только РФ / по выбору клиента)

| Получатель                                | Что получает                                            | Когда                              |
| ----------------------------------------- | ------------------------------------------------------- | ---------------------------------- |
| Yandex Cloud                              | Вся база, файлы, функции API                            | Постоянно (хостинг)                |
| Yandex SpeechKit                          | Выбранное голосовое + тех. id задания                   | Только при согласии на расшифровку |
| ЮKassa / ЮMoney                           | Платёжные данные (не карту целиком — на стороне ЮKassa) | При оплате                         |
| Telegram                                  | Текст/медиа, которые клиент сам отправил в бот          | Если клиент выбрал Telegram        |
| SMS-провайдер                             | Сейчас **не получает** ничего: канал выключен           | —                                  |
| Зарубежные LLM (OpenAI, Anthropic и т.п.) | Клиентские ПДн **не передаются**                        | —                                  |

Аналитика лендинга (Yandex Metrika) — только после отдельного opt-in на сайте; в
дневник клиента не ходит.
