## Что изменилось относительно проекта из третьего разбора

**Добавлено про тренировочную часть.** В проекте речь шла только о питании. Pro
Спорт включает программу тренировок, и противопоказания там свои — оферта это
уже учитывает по решению из C6, предупреждение должно быть согласовано с ней.

**Добавлено, что сведения будут удалены.** Одной фразы достаточно, чтобы
предупреждение работало не только как информирование, но и как часть процедуры
из четырёх мер по свободному вводу: клиент заранее уведомлён, что удаление таких
сведений — нормальный ход, а не потеря его данных.

**Добавлен возраст.** Заявление о достижении 18 лет должно быть сделано активно,
а не выведено из года рождения. Это тот самый пункт из третьего разбора, который
переносил ответственность за недостоверность на сторону, её допустившую. Экран
предупреждения — подходящее место: отдельного акта заводить не нужно.

Само подтверждение остаётся одним вариантом ответа без ветвления и без поля для
комментария. Хранятся факт, версия текста и время — ничего больше.

---

## Условия, при которых это не является обработкой данных о здоровье

Повторяю их здесь, потому что они инвариант, а не разовая проверка:

1. вариант ответа один — «нет» не существует и не сохраняется;
2. сценарий по ответу не ветвится: ни тариф, ни программа, ни пометка куратору
   от него не зависят;
3. хранится только факт, версия и время;
4. поля для комментария рядом с подтверждением нет.

Любое последующее улучшение, нарушающее хотя бы один из четырёх пунктов,
возвращает запись в специальную категорию со всеми последствиями. Стоит
зафиксировать это в плане как инвариант, а не держать в памяти одного человека.
