см. `release-archive.md`). Подписанная оценка после второй вычитки юриста 13.08

  **одноразовый**; (2) приём push-подписок ограничен перечнем допустимых служб

  ~174) принимает любой `endpoint` без проверки хоста.
- **Зависимость:** сначала закрыть или явно развести `prompt-login-pin-diag`.
  Если PIN клиента не работает из‑за рассинхрона v2, одноразовость поверх этого

## Часть 1 · Одноразовый код кандидата

### Что должно получиться

Код из приглашения в анкету (Telegram и т.п.):

- **одно успешное использование**, затем отклонение;
- **короткий срок жизни** (ориентир — как у клиентского onetime: 3 суток в
  `issue_onetime_pin_for_client`,
  `database/2026-08-11_client_login_scheme_v2.sql`);
- **перевыдача куратором гасит предыдущий** немедленно.

Эталон для копирования паттерна — клиентский контур v2:

- `issue_onetime_pin_for_client`, `verify_client_onetime_pin` — тот же файл
  `2026-08-11_client_login_scheme_v2.sql`
- consume: `onetime_pin_consumed_at`, проверка `onetime_pin_expires_at`

### Текст на экране

12.08 формулировку **убрали** («одноразовый» врал). После реализации вернуть
честное «одноразовый код» / «код действует один раз» в:

### Проверка

  `onetime_pin_consumed`).
- Истёкший код → отказ.
- Перевыдача куратором → старый код мёртв, новый работает один раз.
- Property-тест или SQL-smoke по образцу `TESTS/db/client-login-scheme.test.ts`
  — минимум один кейс «второй раз не пускает».

### Миграция

  числом).
- Показать SQL владельцу **до** применения на prod.
- `GRANT` / `REVOKE` как у соседних trial RPC.

## Часть 2 · Белый список служб доставки push

### Что должно получиться

На **`POST /push/subscribe`** (клиент и куратор) принимаются только endpoint'ы с
хостами:

- `fcm.googleapis.com` (Chrome, Android → Google FCM)
- `web.push.apple.com` (Safari → Apple)

Остальные — **400** с понятным `error`, **лог на сервере** (не молча).

### Где менять

| Файл                                            | Что                                                                         |
| ----------------------------------------------- | --------------------------------------------------------------------------- |
| `yandex-cloud-functions/heys-api-push/index.js` | `handleSubscribe` ~174 — проверка **до** INSERT                             |
| (опционально) shared helper                     | одна константа `ALLOWED_PUSH_ENDPOINT_HOSTS` — расширение списка осознанное |

Клиент (`apps/web/heys_push_v1.js` ~218 `pushManager.subscribe`) **не**
считается границей — обходится.

### Требования к реализации

1. **Парсинг хоста** из URL endpoint (не substring по всей строке).
2. **Логирование отклонений**: host, identity kind/id (без ключей p256dh/auth),
   причина `push_endpoint_host_not_allowed`.
3. **Существующие подписки не удалять** — только gate на новые/обновлённые.
4. В отчёте — **аудит prod**:

```sql
SELECT split_part(split_part(endpoint, '://', 2), '/', 1) AS host, COUNT(*)
FROM push_subscriptions
GROUP BY 1 ORDER BY 2 DESC;

SELECT split_part(split_part(endpoint, '://', 2), '/', 1) AS host, COUNT(*)
FROM curator_push_subscriptions
GROUP BY 1 ORDER BY 2 DESC;
```

Если есть хосты кроме двух разрешённых — **сказать прямо**: это меняет текст
уведомления РКН (Firefox/Mozilla, Edge и т.д.).

### Проверка

- Подписка с `https://fcm.googleapis.com/...` → 200, строка в таблице.
- Подписка с `https://updates.push.services.mozilla.com/...` → 400 + запись в
  логе функции.
- Unit-тест в `yandex-cloud-functions/heys-api-push/` (если есть harness) или
  минимальный node-тест парсера хоста — по аналогии с соседними тестами.

### Deploy

`heys-api-push` — отдельный deploy после проверки. **Только по прямой команде
владельца** на push/deploy.

## Критерий готово

1. Кандидатский код одноразовый — доказано тестом/SQL-smoke.
2. Push subscribe режет посторонние хосты с логом — доказано вызовом handler.
3. Копирайт анкеты снова говорит «одноразовый» без расхождения с поведением.
4. Отчёт содержит таблицу фактических push-хостов в базе.
