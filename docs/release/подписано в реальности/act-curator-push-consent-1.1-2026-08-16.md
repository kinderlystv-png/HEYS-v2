## 4. Служебная часть — как акт попадает в систему

Настоящий акт является основанием для записи в `public.curator_consents`:

| Поле               | Значение                     |
| ------------------ | ---------------------------- |
| `consent_type`     | `curator_push_notifications` |
| `document_version` | `1.1`                        |
| `granted`          | `true`                       |
| `consent_method`   | `paper_act`                  |
| `signature_method` | `paper`                      |

Запись вносится миграцией
`database/2026-08-16_activate_curator_push_consent_v1_1.sql`, блок 3, только для
куратора `poplanton@mail.ru`. `document_sha256` проставляется триггером
`enforce_consent_document_proof` из реестра — поэтому регистрация версии 1.1
должна пройти в той же миграции раньше.

**Почему акт, а не экран.** Экрана подписи в профиле куратора нет:
`curator_consents` живёт только на серверной стороне. Пока куратор один и это
владелец, бумажный акт закрывает требование юриста («каждый куратор подписывает
сам») дешевле, чем разработка экрана. **К первому найму экран обязателен:**
наёмный куратор не может подписывать через акт, который сам же и оформляет
работодатель — согласие, полученное под угрозой недопуска к работе, добровольным
не считается (юрист, ответ 7 и правка 3 к кураторскому тексту).

**Хранение.** Подписанный оригинал — у оператора. Этот markdown — канонический
путь в репозитории:
`docs/release/подписано в реальности/act-curator-push-consent-1.1-2026-08-16.md`.
Скан или фотография кладётся рядом под именем
`act-curator-push-consent-1.1-2026-08-16.<ext>`.
