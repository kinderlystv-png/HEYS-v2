# Проверка: данные менструального цикла и граница «только на устройстве»

**Для юриста · HEYS · package-2 · срез 11.08.2026**

Источник вопроса: `docs/release/lawyer-review-2026-08-11.md` §4.

**Правило юриста:** оператор **не обрабатывает** даты/номер дня цикла, только
если они **не покидают устройство совсем**. Достаточно **одного «да»** из
четырёх условий ниже — и вариант «только на устройстве» отпадает: для включивших
функцию нужна **письменная форма** согласия и **паспортные реквизиты** (полный
состав ч. 4 ст. 9 152-ФЗ).

Статусы в таблице: **проверено** = есть grep/read/SQL в этом файле; иначе не
используется в выводе.

## 1.1. Сколько cycleDay уже в базе (прод)

Запрос read-only к **продуктивной** БД (`bash scripts/db/psql.sh`), **2026-08-11
~23:30 МСК**:

| Метрика                                                                         | Значение |
| ------------------------------------------------------------------------------- | -------- |
| Строк дня (`heys_dayv2_YYYY-MM-DD`) с непустым `cycleDay` в `client_kv_store.v` | **44**   |
| Профилей с `cycleTrackingEnabled = true` (ключ `heys_profile`, поле в JSON)     | **3**    |
| Строк дня с непустым `cycleStatus`                                              | **3**    |

```sql
-- cycleDay в дневнике
SELECT COUNT(*) FROM public.client_kv_store kv
 WHERE kv.k ~ '^heys_dayv2_[0-9]{4}-[0-9]{2}-[0-9]{2}$'
   AND NULLIF(kv.v->>'cycleDay', '') IS NOT NULL;

-- флаг в профиле
SELECT COUNT(*) FROM public.client_kv_store kv
 WHERE kv.k LIKE 'heys_profile%'
   AND COALESCE(kv.v->>'cycleTrackingEnabled','false') = 'true';
```

**Вывод по данным:** миграция при переходе на device-only **не обходится
«нулём»** — 44 исторические записи уже на сервере. Нужен purge или явная
политика хранения до решения владельца.

**Примечание:** код минимизации (`heys_health_features_v1.js`) при
**выключенном** трекинге режет новые записи, но **не удаляет** уже лежащие в
`client_kv_store` до отдельной purge-миграции
(`2026-08-11_health_minimization_purge_v1.sql`, **не применена** на проде).

## Вывод для юриста

По четырём проверенным условиям — **все «да»**. Вариант «даты цикла не покидают
устройство» **не выполняется** при текущей архитектуре и уже накопленных данных
(44 строки на проде). При включении функции трекинга цикла для клиенток
действует режим **специальной категории** с требованиями письменной формы и
паспортных реквизитов у включивших — как в §4 разбора юриста.

Отдельное согласие на трекинг цикла и тексты к нему **нельзя финализировать**,
пока владелец не выберет: **переделка на device-only** (смета ниже) **или** сбор
паспортных данных.

## 1.3. Смета: device-only цикл (все четыре «да»)

Оценка для решения владельца, **не план реализации**.

| Поле                         | Оценка                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Затронутые файлы/контуры** | `heys_cycle_v1.js`, `heys_day_utils.js`, `heys_storage_supabase_v1.js` (исключить cycleDay из cloud sync), `heys_day_caloric_balance_v1.js`, `heys_day_water_state.js`, `heys_health_features_v1.js`, `heys-mcp/lib/day.js` (check-in без cycleDay на сервер), `insights/patterns/lifestyle.js`, виджеты/спарклайны с `cycleDay`, `export_my_data_by_session` (фильтр или отсутствие поля), `heys-client-daily-backup` (не копировать cycle-поля), purge SQL |
| **Объём**                    | **L** — ориентир **6–10 рабочих дней**: много точек записи/чтения, MCP и DSAR, регрессия норм и советов                                                                                                                                                                                                                                                                                                                                                      |
| **Продуктовая цена**         | Нет синхронизации цикла между устройствами; при смене телефона история цикла не переносится; куратор/MCP не видит день цикла; паттерны и инсайты по циклу требуют переписывания или отключения; на сервер уходит только **готовая цель дня** (если так решат) — иначе и цель считается на устройстве                                                                                                                                                         |
| **Данные**                   | **44** строки `cycleDay` на проде + 3 профиля с флагом — нужен purge (`health_minimization_purge` или точечный) **до** обещания «на сервер не попадает»; иначе расхождение с согласием                                                                                                                                                                                                                                                                       |
| **Риски**                    | Сделать наполовину: в согласии «только на устройстве», а в `client_kv_store`/DSAR/бэкапе поле остаётся — хуже, чем текущее честное «да»; гейт `stripDisabledHealthFields` не чистит историю                                                                                                                                                                                                                                                                  |

**Альтернатива без переделки:** оставить серверное хранение и принять режим
спецкатегории с паспортными реквизитами у включивших.
