# F. Резервные копии

**Для юриста · HEYS · сверка 11.08.2026**  
Живая проверка кластера Yandex Managed PostgreSQL:
`backup_retain_period_days = 14`.

## Два слоя (их нельзя смешивать)

### 1. Бэкапы базы PostgreSQL (управляемый сервис Yandex)

| Вопрос                                           | Факт                                                                                                                                                                                                                                                          |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Частота                                          | Автоматические снапшоты сервиса + окно бэкапа (в кластере задано, окно стартует около 22:00)                                                                                                                                                                  |
| Срок хранения                                    | **14 дней** (факт настройки кластера `heys-production`)                                                                                                                                                                                                       |
| Point-in-time recovery                           | Да, в пределах окна retention                                                                                                                                                                                                                                 |
| Где                                              | Yandex Object Storage, регион Россия                                                                                                                                                                                                                          |
| Шифрование                                       | Server-side AES-256 (KMS Yandex)                                                                                                                                                                                                                              |
| Круг лиц с доступом                              | Администраторы облака оператора (владелец ИП / лица с ролями в Yandex Cloud). Штатных «сотрудников бэкапа» нет                                                                                                                                                |
| Исключение удалённых клиентов при восстановлении | **Отдельной процедуры нет.** Восстановление — снимок всей БД на момент времени. Если клиента уже удалили из «живой» базы, а бэкапу меньше 14 дней, при полном restore данные клиента могут вернуться из снимка. После истечения 14 дней слой перезаписывается |

### 2. Ежедневные снимки по клиенту (`heys-client-daily-backup`)

| Вопрос               | Факт                                                                                                                                                                                                                           |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Частота              | Ежедневно (отдельная cloud-функция)                                                                                                                                                                                            |
| Срок хранения        | **365 дней** по умолчанию (`RETENTION_DAYS`, код и README функции)                                                                                                                                                             |
| Что внутри           | KV-дневник клиента + часть account-данных (без секретов вроде pin_hash)                                                                                                                                                        |
| Где                  | S3-совместимое хранилище Yandex (`heys-backups/…`)                                                                                                                                                                             |
| Шифрование           | На стороне Object Storage (как у бакета); отдельно заявленное «шифрование копий» в политике как отдельная процедура — в плане отмечено к доработке                                                                             |
| Круг лиц             | Тот же: админы облака / оператор; restore — ручной скрипт по `client_id` и дате                                                                                                                                                |
| Исключение удалённых | **Автоматического реестра «не восстанавливать удалённых» нет.** Скрипт restore принимает конкретный `client_id` и дату; решение не поднимать снимок удалённого клиента — на человеке. Старые объекты живут до ротации 365 дней |

## Что происходит при удалении аккаунта

- В активной БД: данные клиента удаляются сразу (cascade).
- В бэкапе PostgreSQL: остаются до истечения **14 дней**.
- В суточных снимках: объект может оставаться до **365 дней**, пока ротация его
  не сотрёт.
- Принудительно «вырезать» человека из уже сделанного бэкапа Yandex Managed
  PostgreSQL нельзя — только дождаться retention.

## Процедура исключения удалённых при восстановлении

**Нет.** Нет реестра удалённых субъектов, который фильтрует restore. Нет
автоматического пропуска UUID удалённых клиентов при накате снимка. Это открытый
пробел относительно желаемой политики.
