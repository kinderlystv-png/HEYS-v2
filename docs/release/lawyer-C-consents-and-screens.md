## 2. Экраны подтверждения (как сейчас в продукте)

### 2.1. Блокирующий экран в приложении («Перед началом» / повторное согласие)

Источник UI: `heys_consents_v1.js`, способ подписи:
**`signature_method: checkbox`**. SMS-код выключен
(`SMS_VERIFICATION_ENABLED = false`).

Обязательные чекбоксы (кнопка «Продолжить» без них не активна):

1. «Принимаю условия Пользовательского соглашения (Оферты)» → ссылка на
   user-agreement 1.10
2. «Даю согласие на обработку моих персональных данных в соответствии с
   Политикой конфиденциальности» → privacy 1.7
3. «Даю явное согласие на обработку данных о здоровье и ограничениях в целях
   безопасного сопровождения» → health 1.5

Необязательные на том же экране:

4. «Согласен получать информационные и рекламные материалы сервиса»
5. «Напоминания и важные события (статус триала, новые сообщения куратора)»

Что пишется на сервер в момент нажатия «Продолжить» — см. документ **D**.

### 2.2. Оплата

Чекбокс / акцепт: «Нажимая „Оплатить“, принимаю условия Публичной оферты»
(user-agreement 1.10).

### 2.3. Голосовая расшифровка

Отдельный чекбокс перед использованием: «Согласен на передачу голосовых
сообщений в Yandex SpeechKit…» (speech 1.1).

### 2.4. Заявка на лендинге

Отдельный узкий чекбокс: согласие на обработку ПДн **только для заявки и
обратной связи** со ссылкой на политику (версия в UI лендинга — из
`legal-versions.ts`, сейчас 1.7). Это не полный комплект клиентских согласий
приложения.

**Юрист:** один чекбокс, узкая цель — **ок**.

### 2.5. Предтриальная анкета (до минимизации в проде)

На шаге 1 — чекбокс согласия на данные о здоровье кандидата; пишется в
`trial_candidate_consents`, не в клиентскую таблицу `consents` (см. D). После
выката минимизации этот шаг **заменяется** экраном 2.6.

### 2.6. Вход v2 — код доступа и ПЭП (канвас принят, UI в проде ещё не подключён)

Источник макета: `docs/ui/handoff-v4/canvas/Вход v4.dc.html`,
`prompt-login-canvas`. Серверная часть login v2 готова на staging;
`heys_auth_v1.js` **ещё** на `verify_client_pin_v3`.

| Экран                                        | Чекбоксы                                      | Что покрывает                                        | Кнопка без галочек     | signature_method (план)                                       |
| -------------------------------------------- | --------------------------------------------- | ---------------------------------------------------- | ---------------------- | ------------------------------------------------------------- |
| «Придумайте свой код» после одноразового PIN | 1 обязательный: принятие **Соглашения о ПЭП** | ПЭП (проект 1.0), не оферта и не политика            | «Продолжить» неактивна | `access_code` + запись в журнал подписания (сервер)           |
| Подтверждение подписи документа (шторка)     | 0 — ввод кода                                 | конкретный документ (согласие/оферта при подписании) | —                      | `access_code` (всегда с кодом, даже на доверенном устройстве) |

**Юрист:** оферта и согласие на ПДн **не** объединены с чекбоксом ПЭП на одном
экране — **ок**. ПЭП — отдельный документ и отдельная галочка.

### 2.7. Анкета после минимизации (код 11.08, миграции не в проде)

Один экран предупреждения вместо шагов «Здоровье» / «Безопасность»; один вариант
ответа (подтверждение). Текст предупреждения: **`pending-owner-text`** — в
пакете **нет**, ждёт владельца.

| Экран                 | Чекбоксы                       | Риск «оферта + согласие в одном»           |
| --------------------- | ------------------------------ | ------------------------------------------ |
| Предупреждение intake | 1 (подтверждение ознакомления) | **ок** — не смешивает с офертой приложения |

### 2.8. Опциональные функции (цикл / замеры / добавки)

Источник: `heys_health_features_v1.js` — по умолчанию **выкл.**; включение через
`requestHealthFeatureToggle` с экраном согласия.

| Функция       | consentType            | Текст согласия       | Чекбокс              |
| ------------- | ---------------------- | -------------------- | -------------------- |
| Трекинг цикла | `cycle_tracking`       | `pending-owner-text` | отдельный, не оферта |
| Замеры тела   | `body_measurements`    | `pending-owner-text` | отдельный            |
| Добавки       | `supplements_tracking` | `pending-owner-text` | отдельный            |

**Юрист:** три отдельных согласия, не объединены с офертой — **ок**. Тексты **не
готовы** для разбора.

**Связь с циклом:** см.
[lawyer-cycle-device-check.md](./lawyer-cycle-device-check.md) — при текущей
архитектуре все четыре условия «да».

## 3. Скриншоты экранов

**Статус на момент сборки пакета:** живых скриншотов PIN-сессии в репозитории
нет. Для юриста нужны минимум:

1. Блокирующий экран «Перед началом» с тремя обязательными чекбоксами и кнопкой
   «Продолжить»
2. Тот же экран с раскрытой ссылкой/модалками на тексты (оферта / политика /
   здоровье)
3. Экран оплаты с акцептом оферты (если показываете платный контур)
4. Чекбокс голосовой расшифровки (если оставляете функцию в scope)
5. Чекбокс согласия на лендинге у заявки

Снять с рабочего аккаунта (2–3 минуты) и положить в
`docs/release/lawyer-C-screens/` либо приложить к письму юристу рядом с этим
файлом. Без скринов тексты всё равно читаются из `lawyer-C-texts/`; скрины нужны
как доказательство того, **что именно видит человек на экране**, а не только что
лежит в файле.

## 4. Известные расхождения (честно)

- `docs/legal/consent-forms.md` местами ещё пишет версии 1.9 для оферты —
  **устарело**; боевые версии — **1.10 / 1.7 / 1.5** (код + manifest + public
  snapshots).
- В текстах согласий ещё фигурируют формулировки под прежнюю полноту анкеты
  «здоровье»; решение 11.08 убрать медвопросы из анкеты **в тексты ещё не
  внесено** (новый цикл версий + переподписание).
- В соглашении остаются пункты про трансграничную передачу / ПЭП-хвосты, которые
  в плане релиза помечены к правке в версии **1.11** — **сейчас юрист читает
  1.10 как есть** (флаг «устареет в 1.11»: медполя анкеты в health 1.5,
  трансграничка в оферте, `sms_code` в примере §8.3 ПЭП).
- ПЭП: проект в `soglashenie-pep.md`, **не в manifest**, экран только в канвасе
  — до выката login v2 на фронте.
- Цикл: [lawyer-cycle-device-check.md](./lawyer-cycle-device-check.md) — все
  четыре условия «да»; согласие `cycle_tracking` = `pending-owner-text`.
