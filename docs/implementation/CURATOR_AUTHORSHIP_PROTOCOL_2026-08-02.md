# Протокол: запись куратора × утренний чек-ин

Задача с доски: «Провести аудит связки „запись куратора × утренний чек-ин“» → по
итогам аудита пользователь поручил закрыть все найденные дефекты.

Аудит и его опоры живут в
[heys-mcp/README.md](../../yandex-cloud-functions/heys-mcp/README.md), раздел
«Запись куратора × утренний чек-ин — аудит 2026-08-02». Здесь — только ход
работы и что смотреть ревьюеру.

## Шаг 1. Производные поля дня в коннекторе — сделано

**Что было.** `heys_update_day` писал в производные поля блоба вместо
источников, и приложение их перезаписывало или не видело вовсе:

| Поле                    | Было                                       | Стало                                                                  |
| ----------------------- | ------------------------------------------ | ---------------------------------------------------------------------- |
| `sleepHours`            | не пересчитывался при смене времён сна     | пересчёт в `touch()`                                                   |
| `mood/wellbeing/stress` | писались в `moodAvg/*Avg` (средние по дню) | пишутся в `moodMorning/*Morning`, средние и `dayScore` пересчитываются |
| `steps`                 | без `stepsUpdatedAt`                       | штамп ставится, как для веса                                           |

**Решение.** Пересчёт производных сведён в `touch()`
([lib/day.js](../../yandex-cloud-functions/heys-mcp/lib/day.js)) — единую точку
фиксации мутации дня. Входы средних меняются в четырёх инструментах (чек-ин,
приём, правка приёма, тренировка), поэтому точечный пересчёт в `updateDayFields`
закрывал бы только один из них.

`dayAverages()` повторяет формулу приложения
([heys_day_calculations.js:155](../../apps/web/heys_day_calculations.js)):
среднее по утренней оценке, оценкам приёмов и реальных тренировок; `dayScore` не
трогается при `dayScoreManual`.

**Проверка.** `node --test __tests__/*.cjs` в `heys-mcp` — 255/255, из них 8
новых регресс-тестов в `day.test.cjs`.

**Риск для ревьюера.** `isRealTraining` в коннекторе повторяет критерий
приложения приближённо: ветка `workout_builder` не вызывает
`workoutLogHasTrackableContent`, а проверяет наличие объекта. Расхождение
возможно только для strength-заготовки с пустым `workoutLog` и выставленной
оценкой; приложение пересчитает среднее при открытии дня.

**Смена контракта.** `mood/wellbeing/stress` в `heys_update_day` теперь означают
утреннюю отметку, а не «оценку за день» — описания в схеме инструмента
обновлены. `summarizeDay` дополнительно отдаёт блок `morning`, чтобы куратор
видел и свою отметку, и среднее по дню.

## Шаг 2. Кураторская правка шагов в фиде действий — сделано

`diffDayv2` читал `oldDay.stepsCount`, которого в блобе дня нет (поле —
`steps`), поэтому `steps_set` не появлялся в `client_data_changelog` никогда.
Исправлено в
[curator-action-diff.js](../../yandex-cloud-functions/heys-api-rpc/curator-action-diff.js),
тест закреплял ошибочное имя — обновлён.
`node --test __tests__/curator-action-diff.test.js` — 31/31.

## Шаг 3. Авторство записи — сделано

**Формат.** `_curatorEdits: { <поле>: { at, value } }` в блобе дня. Метка хранит
значение куратора, поэтому самоочищается при расхождении; подтверждение клиента
гасит её явно (`{ at, value: null }`). Полный контракт — в README-аудите, раздел
«Контракт метки авторства».

**Почему не проще.** Разведка показала два места, где новое поле умирает молча:
`mergeDayData` строит результат как `{ ...remote }`, а `ensureDay` собирает день
перечислением полей без спреда. Поэтому метка добавлена в оба — плюс union по
образцу `deletedMealIds` (`unionCuratorEdits`).

**Что изменено.**

| Слой                   | Файлы                                                                                               |
| ---------------------- | --------------------------------------------------------------------------------------------------- |
| Запись                 | `heys-mcp/lib/day.js`, `lib/tools.js`, `lib/curator.js`                                             |
| Сохранность            | `heys_sync_merge_v1.js` + две зеркальные `.cjs`, `heys_models_v1.js`                                |
| Гашение вводом клиента | `heys_steps_v1.js` (4 шага), `heys_day_main_block_v1.js`                                            |
| Видимость              | `heys_day_side_block_v1.js`, `heys_day_main_block_v1.js`, `styles/modules/200-dark-and-effects.css` |
| Дисциплина             | `heys_morning_checkin_v1.js`, `heys_cascade_card_v1.js`, `heys_gamification_v1.js`                  |

**Продуктовое решение, которое стоит отдельно назвать.** Поле с действующей
меткой больше не закрывает шаг чек-ина. Альтернатива — оставить шаг закрытым —
отклонена: тогда клиента не спрашивают, а стрик по этому дню всё равно не
растёт, и он теряет его молча. Теперь клиент подтверждает значение (оно уже
предзаполнено кураторским), метка гаснет, стрик идёт.

**Проверки.** `heys-mcp` 255/255, `curator-action-diff` 31/31,
`TESTS/regressions/task-003-checkin-*` 19/19, полный web-набор 3584 passed / 0
failed, новый `curator-authorship.test.js` 9/9.

**Что проверено на проде и что осталось.** Цепочка данных замкнута и проверена
живьём на тестовом клиенте `E2E-TestPopl`: `heys_update_day` с `mood=7` и
`steps=4321` → `heys_get_day` отдаёт
`curator_authored: ["moodMorning", "steps"]` и `morning.mood: 7`. То есть
коннектор метку ставит, серверный merge сохраняет её union'ом, чтение
возвращает. Открытым остаётся только рендер: пометку «✎ куратор» в карточке дня
никто не видел глазами. Она закрыта контрактным тестом, а данные для проверки
уже лежат в дне `E2E-TestPopl` — достаточно открыть этого клиента в приложении.

**Побочный фикс по пути.** В ретро-выдаче `first_checkin` условие читало
`parsed.morningMood` — поля с таким именем в блобе нет (правильное —
`moodMorning`), то есть утренняя оценка ачивку не выдавала никогда.

## Выкат: две волны — договорённость 2026-08-02

Работа поделена между двумя параллельными сессиями, которые правили одни файлы
`heys-mcp`. Согласовано напрямую, ownership разведён по функциям:

| Волна | Кто                                | Что уезжает                                                                                                   | Статус                                     |
| ----- | ---------------------------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| 1     | сессия «MCP клиентам через Cowork» | `heys-mcp` целиком — её строгая адресация записи плюс вся правка производных полей и меток из этого протокола | `9847ac745`, задеплоено вручную            |
| 2     | эта сессия                         | `heys-api-rpc`, `heys-api-rest` (union меток в merge) и веб-половина                                          | `94994f2c2`, задеплоено CI, деплой зелёный |

**Выкачено и проверено на живом проде (2026-08-02).**
`app.heyslab.ru/build-meta.json` отдаёт `94994f2c`; в боевых бандлах
`boot-core`, `boot-day` и `postboot-3-ui-lazy` присутствуют `isCuratorAuthored`,
`clearCuratorMarks` и `curator-authored-hint`. Функции `heys-api-rpc` и
`heys-api-rest` несут `HEYS_DEPLOY_COMMIT=94994f2c`, `heys-mcp` — `9847ac74` (CI
не переливает функцию, которой коммит не касался). Фича больше не половинчатая:
коннектор метки ставит, серверный merge их сохраняет, клиент показывает и гасит.

**Деплой остановлен внешней причиной, не кодом (2026-08-02).** Проверено
самостоятельно через `yc`: API Gateway `heys-api`, `kinderly-api` и
`kinderly-contracts-api` в статусе `STOPPED`, кластер `heys-production` —
`STOPPED` при `HEALTH: ALIVE`, функции `heys-mcp` и `heys-api-rpc` остались
`ACTIVE`. `api.heyslab.ru` и `heyslab.ru` не отвечают, при этом сторонний домен
из той же среды открывается — то есть недоступность не сетевая. Ресурсы погашены
`yc.iam.reaper` при блокировке платёжного аккаунта. Данные целы: кластер жив,
его нужно только запустить.

**Что именно гасит фронт — не gateway, а отдельная ВМ.** После восстановления
шлюза и кластера `api.heyslab.ru` отвечал, но `app.heyslab.ru` и `heyslab.ru`
продолжали молчать, и CI-деплой падал на шаге «Verify production build metadata»
с пустым `REMOTE_HASH` — то есть верификация не достучалась до фронта, хотя
артефакт уже был выложен. Причина: оба домена резолвятся в `158.160.53.194`, это
ВМ `app-heyslab-proxy`, и она осталась `STOPPED`. После
`yc compute instance start app-heyslab-proxy` фронт и лендинг ответили `200`,
повторный прогон деплоя стал зелёным. При следующем гашении reaper'ом поднимать
нужно **три** вещи: шлюз `heys-api`, кластер `heys-production` и эту ВМ.
Отдельно замечено: CDN-ресурсы `heyslab.ru`, `try.heyslab.ru`,
`genda.heyslab.ru` числятся неактивными — трафик идёт через ту же ВМ.

**Ресурсы гасятся во всех папках, а `yc ... list` показывает только текущую.**
Из-за этого при первом разборе подняли три шлюза из пяти: `mine2d` и
`bakshepchet` остались лежать и вскрылись случайно. Обходить надо по списку
папок: `yc resource-manager folder list`, затем
`yc serverless api-gateway list --folder-id <id>` и то же для `compute instance`
и `managed-postgresql cluster`. Итоговая проверка после восстановления
(2026-08-02): пять шлюзов `ACTIVE`, кластер `heys-production` `RUNNING`, ВМ
`app-heyslab-proxy` `RUNNING`, других остановленных ресурсов в четырёх папках
нет. Правило для диагностики: «API отвечает, приложение молчит» — смотреть ВМ, а
не шлюз.

Пока прошла только первая волна, фича «авторство» считается **невыкаченной**, а
не полурабочей: коннектор метки пишет, но серверный merge в конфликтной ветке
строит результат от `remote` и их отбрасывает, а на клиенте их всё равно срезает
старый `ensureDay`. Порчи данных нет — метка живёт отдельным ключом и ни на одно
значение дня не влияет. Что первая волна чинит сама по себе: неверные часы сна,
пропадающие оценки и шаги без `stepsUpdatedAt`.

**Чем заблокирована вторая волна.** Коммит `heys-api-rpc` тянет за собой
`apps/web/heys_sync_merge_v1.js`: гейт `lint-sync-merge-cjs-mirror` сверяет
staged-версии ESM и обоих зеркал, порознь они не проходят. Как только в коммит
попадает веб-исходник, включается `legacy-sync` и упирается в грязный generated
— `apps/web/bundle-manifest.json`, `public/bundle-manifest.json` и
`public/sw.js` заняты третьей сессией (messenger-редизайн). Хук намеренно не
прячет чужой WIP. Разблокируется, когда та сессия закоммитит своё.
