# Протокол реализации — Landing D (`/v/d/`)

Задача: `маркетинг/22` п. 3.17, решение владельца `маркетинг/15` №50
(2026-08-02). Канон дизайна:
[`apps/landing/design/landing-d/README.md`](../../apps/landing/design/landing-d/README.md).

Протокол для ревьюера: крупные шаги, их статус и чем проверено. Подробности
решений — здесь, в чат уходит только короткий итог шага.

## Рамки задачи

- Версия `D` собирается **целиком и отдельно** на `/v/d/`. Слияние её элементов
  в `C` отклонено владельцем: проверяется структура страницы целиком.
- Публика видит `A`; `B`, `C`, `D` — черновики без ссылок с публичной страницы,
  `noindex`, доступны владельцу через FAB по признаку «свой».
- `COPY_VOICE — предложение v19.md` из handoff **не применяется**: v19 уже в
  дереве (`ae188ce8e`). Источник правды —
  [`apps/landing/COPY_VOICE.md`](../../apps/landing/COPY_VOICE.md).
- Цены только из `PRICING`, реквизиты из `OPERATOR`, контракт заявки — из
  `TrialForm` / `PurchaseModal`.
- Ёмкость набора — без счётчика мест до реального источника (`17` § 3.5).

### Условия из ревью пакета (входят в задачу)

1. «3–5 минут в день» → «обычно 3–5 минут в день» в трёх местах: подзаголовок
   героя, шаг 01 секции 02, ответ №1 FAQ. Число сохраняется; фактический замер
   времени клиента — задача первых пробных недель.
2. Таймкоды отбивок hero-демо выносятся из кода в JSON рядом с видео + проверка
   длительности файла: не совпала — отбивки не показываются.
3. Квиз проектируется версионно-независимым: при выборе `C` переезжает без
   переделки. Поэтому он живёт не в `versions/d/`, а в общей папке.

### UI-гейт (обязательная строка перед UI-правкой)

`UI-гейт: цель — довести холодного посетителя до заявки на неделю Pro; главное действие — «Неделя Pro — 0 ₽» (герой → липкий CTA → форма); слой 1 — ситуация, механика, артефакт недели, цена, заявка; слой 2 — <details> «сравнить форматы», «как устроено сопровождение», «а если неделя не задалась», FAQ; критическое не скрывать — медицинские границы, «куратор живой человек», условия возврата и отсутствие автосписаний, обязательные согласия формы.`

## Журнал шагов

### Шаг 0 — публичный переключатель погашен

`TEMPORARY_PUBLIC_SWITCHER = false` в
[`VersionSwitcherFab.tsx`](../../apps/landing/src/components/VersionSwitcherFab.tsx).
Признак «свой» (localhost / `heys_dev_mode` / `?owner=1`) снова единственное
условие показа; логика под флагом не тронута, комментарии приведены в
соответствие. Проверено: `tsc --noEmit` = 0, ESLint по файлу = 0.

Риск: владелец теряет возможность открыть черновики с чужого устройства без
`?owner=1`. Это осознанная цена — иначе с появлением `D` с публичной страницы
достижимы три незаконченных черновика.

### Шаг 1 — handoff в дерево

Пакет положен в `apps/landing/design/landing-d/`: `README.md` (канон),
`prototype.html` + `prototype-mobile.html` + `support.js` + `image-slot.js`
(прототип, открывается в браузере напрямую), `screenshots/` (42 референса).

Видео демо **не копировалось**: `hero-curator-demo.{webm,mp4}` и постер в
`apps/landing/public/` побайтово совпадают с файлами пакета (md5 сверен).
Фактическая длительность ролика — 63.80 с (`ffprobe`), это опорное значение для
guard'а из шага 10.

`COPY_VOICE — предложение v19.md` в дерево не переносился — он уже применён.

### Шаги 2–10 — версия собрана

Роут `/v/d/`, композиция `versions/VersionD.tsx`, блоки в `versions/d/`:
`HeroD`, `PainSection`, `HowItWorks`, `FirstMonth`, `ReviewedWeek`,
`CuratorSection`, `PricingD`, `TrialSection`, `FaqD`, `FooterD`, `NavD` (липкая
шапка + бургер + липкий CTA в одном компоненте — они делят одно наблюдение за
прокруткой), плюс `primitives.tsx`, `theme.ts`, `fonts.ts`, `LogoD.tsx`,
`nav.ts`, `useReveal.ts`. `D` добавлена в `landing-versions.ts`.

Отступления от handoff и их причины:

- **Квиз лежит не в `versions/d/`, а в `components/quiz/`** — по условию
  версионной независимости. Логика и тексты сегментов — в `quizModel.ts` (чистый
  модуль без React, вопросы и коды сверены с `17` §§ 3.1–3.3), разметка — в
  `TrialQuiz.tsx` и опирается на CSS-переменную `--da`, которую задаёт обёртка
  версии. Переезд на `C` = отрисовать её в другой обёртке.
- **Модалка Pro Спорт — существующий `PurchaseModal`**, а не вёрстка из макета.
  Причина: один контракт заявки важнее пиксельного совпадения. Пункт для
  приёмки: оформление модалки отличается от макета.
- **Контракт заявки вынесен в `src/lib/leads.ts`** и используется формой `D`.
  Боевой `TrialForm` версии A на него НЕ переведён: автотестов у него нет, а
  рефакторить работающий приём заявок ради стройности — несоразмерный риск. Пока
  живы обе версии, изменение контракта правится в двух местах; когда владелец
  выберет основную версию, проигравшая форма уйдёт вместе с копией.
- **`HeroFlowDemo` параметризован** (`containerClassName`, `frameClassName`,
  `controlClassName`, `showChapters`) вместо форка. Дефолты равны прежним
  строкам, поэтому вид версий `A` и `C` не изменился.
- **Точки-главы** живут в том же компоненте и берут главы из JSON-разметки.

### Шаг 10 — таймкоды в JSON и защита по длительности

`public/hero-curator-demo-chapters.json` — отбивки, пропуски дефектных отрезков,
главы и `expectedDuration: 63.8` (замер `ffprobe` по файлу в `public/`).
`HeroFlowDemo` грузит файл при монтировании и на `loadedmetadata` сравнивает
фактическую длительность с ожидаемой (допуск 0.35 с): не совпало — отбивки,
пропуски и главы отключаются, ролик просто играет целиком.

Отступление от формулировки условия: гасятся не только отбивки, но и пропуски.
Они привязаны к тем же таймкодам, и после перемонтажа давали бы случайные скачки
— то есть ломали бы ролик заметнее, чем пропавший эффект.

Встроенный дефолт с прежними таймкодами оставлен: если JSON не доехал (сеть,
кэш, ошибка деплоя), публичная версия `A` не должна терять отбивки.

### Шаг 8 — что уходит куратору вместе с заявкой

Плашка «Куратор увидит: …» обещает передачу контекста, поэтому серверная часть
доведена в этой же задаче:

- `database/2026-08-02_leads_quiz_details.sql` — `leads.quiz_details JSONB`
  (**миграция не применена**, применение — отдельное разрешённое действие);
- `heys-api-leads`: приём `quiz_details`, фильтр `cleanQuizDetails` (только
  ключи `frequency` / `barrier` / `goal`, только коды, до 32 символов —
  свободный текст с публичной формы в карточку лида не пускаем), запись в
  INSERT. **Функция не задеплоена.**

Тип срыва уходит в уже существующее поле `quiz_segment`. До применения миграции
и деплоя функции уточнения будут отбрасываться сервером — это единственное
место, где страница пока обещает больше, чем доезжает.

Ограничение измерения: отдельного HTTP-эндпойнта событий у лендинга нет
(`api-gateway-spec-v2.yaml` знает `/leads`, `/rpc`, `/rest`, `/auth`, `/bot`).
Поэтому `quiz_start` / `quiz_complete` отдельными событиями не шлются: воронка
восстанавливается по заявке (`record_funnel_event` на стороне `heys-api-leads`),
а те, кто начал разбор и не оставил контакт, не измеряются. Закрывается либо
новым эндпойнтом событий, либо решением, что этой точности достаточно.

### Шаг 11 — проверки

Статические: `tsc --noEmit` = 0, `eslint src` = 0 ошибок (остался один дочерний
warning в `HeroFlowDemo` про `videoRef.current` в cleanup — он был в файле до
этой задачи и не трогался), `prettier --write` по своим файлам, `node --test` в
`heys-api-leads` — 10/10 (два теста добавлены на `quiz_details`).

Живой проход на `pnpm --dir apps/landing exec next dev` (порт 3003 занят
параллельной сессией, поднят свой на 52578):

- все девять секций и футер на месте, тексты соответствуют handoff;
- квиз проверен по ветке «Не понимаю» → «Вечером» → сегмент `evening`, три
  уточнения, переход к форме, плашка «Куратор увидит: Вечерний срыв ·
  повторяется: … · сложнее всего: … · цель: …»;
- скролл-зум героя: `scale` растёт по прогрессу, текст гаснет, отступ кнопки
  компенсируется (89 px при `maxScale` 1.12);
- липкая шапка появляется только при движении вверх и не показывается внутри
  героя; липкий CTA виден между «Ваша ситуация» и заявкой и только на узких
  экранах;
- горизонтального переполнения нет; таблица сравнения скроллится внутри себя;
- `reveal` fail-open: все помеченные блоки в конце имеют `opacity: 1`.

**Найдено и исправлено по ходу проверки.** Первая сборка героя клала контент
внутрь липкого слоя с `overflow: hidden`: при 812 px по высоте кнопка «Понять,
как работает HEYS» и точки-главы срезались полностью (контент героя ~1240 px).
Исправлено разделением: липкая обёртка нулевой высоты держит фон, контент лежит
поверх и прокручивается. Отдельно скролл-зум отключён на экранах уже 1024 px —
там он не нужен и мешает.

**Ложный сигнал, чтобы не искали снова.** На скриншотах панели предпросмотра
после программной прокрутки сверху появляется чёрная полоса. Это артефакт
панели, а не вёрстки: на существующей версии `C` он воспроизводится один в один.
Проверять геометрию нужно измерениями DOM, а не скриншотом.

**Чего проверка не покрыла:** реальное мобильное устройство (панель
предпросмотра отдавала рассогласованные `innerWidth`/`clientWidth`), отправка
заявки в боевой `/leads`, поведение отбивок после реальной перемотки
пользователем.

### Что из дизайн-пакета лежит в репозитории

В дереве версионируется только текстовая часть (340 КБ): `README.md` — канон, на
который ссылаются `22` п. 3.17 и этот протокол; `prototype.html`,
`prototype-mobile.html`, `support.js`, `image-slot.js` — эталон поведения,
который читается диффом и открывается в браузере напрямую.

Референс-скриншоты (32 файла, 2.8 МБ) в репозиторий не берутся и закрыты
правилом в `.gitignore`. Причина: это производные — они пересобираются открытием
того же прототипа, — а бинарники в истории git необратимы. Локально они остаются
на месте, у автора дизайна — тоже.

Отличие от прецедента с пакетом редизайна мессенджера, где в репозиторий не
копировали ничего: там канон остался у автора и в дереве на него не ссылались.
Здесь `README.md` уже назван источником правды в задаче `22`, поэтому он должен
пережить сессию вместе с ней.

### Тесты на версию D (после коммита `711a34fb7`)

Версия уехала в коммит без единого автотеста — при том что у неё есть две вещи,
регресс в которых глазами в диффе не виден.

**`quizModel.test.ts` — контракт с ботом.** Квиз лендинга и бот HEYS Старт
обязаны давать один тип срыва по одним ответам (`17` §§ 3.1–3.3): куратор
получает сегмент из обоих каналов. Зафиксирована вся таблица переходов, включая
`unknown` без ответа про время (→ `mixed`), совпадение кодов вариантов и запрет
обещаний по весу/срокам в текстах результатов. 17 проверок.

**`versionD-positioning.test.ts` — пять точек вникания.** README прямо
предупреждает: выпадет одна — страница вернётся к защите копируемого. Тест
читает исходники (не рендерит: проверяются формулировки, и падать из-за
`next/font` или jsdom он не должен) и стережёт порядок реплик в переписке
(вопрос → ответ клиента → шаг), порядок узлов артефакта (заметил → уточнил →
следующий шаг), формулировки героя, секции доверия и карточки заявки. Плюс
границы из `COPY_VOICE`: «обычно» рядом с каждым упоминанием 3–5 минут,
отсутствие слова «забота», отсутствие счётчика мест, отсутствие гарантий, цены
только из `PRICING`, реквизиты только из `OPERATOR`. 14 проверок.

Тест проверен на способность падать: убрал из переписки уточняющий вопрос —
точка 2 упала (`expected -1 to be greater than -1`), после возврата фразы снова
14/14, файл восстановлен побайтово (`git diff` пуст).

Итог по лендингу: `vitest run apps/landing/src/components/__tests__/` — 4 файла,
40 тестов, все проходят (два прежних файла не трогались).

Две правки в самом тесте по ходу — обе мои, не кода: чтение исходника со
схлопнутыми пробелами (prettier переносит длинные строки JSX, и фраза целиком в
файле не встречается) и снятие ложного срабатывания на «не гарантирует» — это
как раз снятие обещания, которое обязано стоять под кнопкой.
