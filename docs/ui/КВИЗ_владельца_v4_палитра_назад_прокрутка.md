## Q1. Палитра (тема) — где живёт выбор?

### Контекст

Сейчас в коде (`heys_theme_v1.js`, шторка `heys_app_shell_v1.js` ~5433):
песочная / синяя / тёмная / сине-тёмная пишутся в **localStorage** на
устройстве. Остальные переключатели настроек идут в **профиль клиента** и
синкаются в облако.

Контракт `settings-system`, строка **`что пишется`:**

> все переключатели и чипы пишутся в профиль человека и синхронизируются между
> его устройствами; **локально в браузере не остаётся ничего, кроме выбранной
> палитры — она нужна до загрузки профиля**

Вердикт сейчас: `≠` — «палитра не в профиле cloud».

### Варианты

|       | Что будет                                                                                                                                                         |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A** | **Как в контракте:** палитра в облачном профиле + **локальный кеш** для первого пейнта до прихода профиля; после логина — читаем из облака, миграция LS → профиль |
| **B** | Палитра **всегда только локально** — тогда нужно **переписать строку контракта** (отклонить синк темы)                                                            |
| **C** | Палитра только в облаке, **без** локального кеша — на cold start до sync всегда дефолт (песочная), потом скачок темы                                              |
| **D** | Свой вариант (опиши)                                                                                                                                              |

### Рекомендация: **A**

Совпадает с контрактом: тема на втором телефоне подтягивается, а «до профиля» не
ломаем — без кеша будет мигание или неверная тема на старте. Цена: миграция,
поле в профиле, порядок «LS → cloud → LS как зеркало».

## Q2. Аппаратная «назад» без открытых слоёв — куда?

### Контекст

Контракт `home-widgets`, **`аппаратная кнопка назад · правило продукта`:**

1. Сначала закрываются слои: лист, модалка, режим правки виджетов…
2. **Когда слоёв нет** — не выход из приложения, а **«предыдущая вкладка в
   порядке навигации»**
3. Выход из приложения — только с **Главной** без слоёв (и на входе / сплэше)

Сейчас (`≠` в снимке): часть слоёв в историю не пишется; **вкладки в стек не
пишутся** — без слоёв «назад» часто **выкидывает из приложения** (типичная
жалоба на Android).

Нижняя навигация (основные вкладки): **Главная → Питание → Актив → Отчёты →
Инсайты** (`app-nav-v4-frame.test.js`).

### Варианты

|       | Что будет                                                                                                         |
| ----- | ----------------------------------------------------------------------------------------------------------------- |
| **A** | **Стек посещений:** «назад» = вкладка, с которой пришли (Питание → Главная → снова Питание, если так ходили)      |
| **B** | **Кольцо навбара:** «назад» = вкладка **левее** в нижней панели (с Отчётов → Актив, с Главной — выход или ничего) |
| **C** | **Кольцо навбара вправо:** «назад» = вкладка **правее** в панели                                                  |
| **D** | **Всегда Главная** (если не на Главной — туда; с Главной — выход)                                                 |
| **E** | **Как сейчас** — без слоёв выход из приложения; контракт переписать                                               |
| **F** | Свой вариант (опиши порядок)                                                                                      |

### Рекомендация: **A**

«Предыдущая вкладка» для человека = откуда пришёл, не сосед в панели. Кольцо
(B/C) непредсказуемо, если вкладки тапали не по порядку. Нужен стек в
`heys_app_shell_v1.js` + тесты на popstate / Android back.

### После ответа в коде

- стек вкладок + закрытие слоёв через общий dismiss;
- вердикт `home-widgets · аппаратная кнопка назад · правило продукта`;
- тест: сценарии «слой → вкладка → выход только с Главной».

## Q3. Прокрутка при смене вкладки

### Контекст

Контракт `home-widgets`, **`прокрутка · правило продукта`:**

- **Смена вкладки**, **смена даты**, повторный тап той же вкладки в навбаре →
  **прокрутка в начало**
- **Память позиции** — только когда ушли **вглубь** (модалка, лист) и
  **вернулись назад** на тот же экран
- Две прокрутки одновременно нет: лист держит фон неподвижным

Сейчас (`heys_app_shell_v1.js` ~6123–6140): при переходе на **Питание** позиция
**восстанавливается** после прошлого визита; остальные вкладки открываются
сверху. Смена даты сбрасывает — это верно.

Вердикт: `≠` — для Питания поведение **против** общего правила (в комментарии
кода ссылка на локальную строку `nutrition-tab · прокрутка` — отдельный спор).

### Варианты

|       | Что будет                                                                                                                                                  |
| ----- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A** | **Контракт буквально:** любая смена вкладки → начало; память **только** при возврате из модалки/листа **внутри** вкладки (Питание не исключение)           |
| **B** | **Исключение для Питания:** дневник помнит прокрутку при переключении вкладок; остальные — как в контракте; общую строку `home-widgets` уточнить в канвасе |
| **C** | **Все вкладки** помнят прокрутку при переключении (как сейчас частично у Питания) — контракт переписать                                                    |
| **D** | Свой вариант                                                                                                                                               |

### Рекомендация: **A**

Одно правило на все вкладки — меньше сюрпризов. Исключение для Питания (B)
оправдано только если дневник длинный и сброс раздражает; тогда это **явное**
отступление в контракте, не молчаливый код.

### После ответа в коде

- правка `scrollMemoryRef` / эффектов в `heys_app_shell_v1.js`;
- при A — убрать восстановление scroll при `tab === 'diary'`;
- вердикт `home-widgets · прокрутка · правило продукта`;
- тест на смену вкладки и возврат из листа.
