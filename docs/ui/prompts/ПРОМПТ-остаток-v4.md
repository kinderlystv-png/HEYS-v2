# Сведение HEYS-v2 с контрактом дизайна v4 — остаток работы

Репозиторий `HEYS-v2`, ветка `main`, работать прямо в ней. Задача — довести код
до дизайн-контракта v4. Из 1487 строк контракта закрыто 1437; осталось 50.

---

## 1. Как устроена приёмка

Контракт живёт строками в канвасах дизайнера:

```
docs/ui/handoff-v4/canvas/Переработка дизайна приложения/design_handoff_heys_v4/<зона>.v4.dc.html
```

Каждая строка — `<div class="spec"><b>КЛЮЧ</b><span data-v="ТЕКСТ ТРЕБОВАНИЯ">`.

Вердикт по каждой строке лежит в `docs/ui/ui-v4-contract-verdicts.json`:

```json
"ключ строки": { "v": "=", "f": "факт: где это в коде", "h": "отпечаток" }
```

- `=` код выполняет строку
- `≠` не выполняет
- `?` спорно или заблокировано чужим решением
- `—` строка только про канвас, кода не касается

`h` — отпечаток текста строки. Дизайнер правит канвас своими коммитами и меняет
`data-v` молча, поэтому гейт `scripts/ui-v4-check-contract-drift.mjs` падает,
когда строка изменилась, появилась или исчезла. Разобрал изменение — поставь
новый вердикт и перехешируй.

**Начни с `node scripts/ui-v4-check-contract-drift.mjs --list`** и перечитывай
свои строки в самом канвасе перед каждым крупным блоком: пакет дизайна правится
по ходу.

### Как ставить вердикт

```bash
node scripts/ui-v4-set-verdict.mjs <зона> "<ключ>" "<вердикт>" "<факт>"
```

Он меняет только `v` и `f`, отпечаток не трогает — тот принадлежит тексту строки
в канвасе, а не нашему мнению о ней. Если дизайнер текст правил, гейт скажет, и
тогда нужен пересчёт `h`.

**Факт — это адрес в коде, а не пересказ строки.** «Сделано» фактом не является.
Пиши `файл:строка` и что именно там лежит. Если строка выполнена наполовину,
пиши, какая половина и почему вторая не сделана.

## 2. Правила, которые нельзя нарушать

**Продуктовую логику не меняй молча.** Владелец сказал дословно: «если меняешь
продуктовую логику, всегда уточняй у меня, потому что макет может врать». Если
строка требует поведения, которого в продукте нет, — сначала вопрос, потом код.
Уже трижды оказывалось, что права не строка, а код.

**Контракт старше кадра.** Кадр рисует одно, строка говорит другое — верна
строка, а отступление называется вслух: в отчёте и поимённо в списке исключений
теста сверки.

**Отрицательный вывод требует двух способов.** «Такого в коде нет» — утверждение
обо всём множестве. Проверь вторым способом: поиск по другому признаку, полный
список глазами, пересчёт целого. И говори «искал по X в Y — не нашёл», а не
«этого нет».

**Кириллица ищется только через `rg`.** Локаль пустая, `grep -i` не сворачивает
регистр кириллицы. Один раз из-за этого в задание уехал ложный факт.

**Коммиты — source-only, явными путями:**

```bash
HEYS_COMMIT_SOURCE_ONLY=1 HEYS_ALLOW_MULTI_ZONE=1 git commit -F <файл-сообщения> -- <явные пути>
```

Флаг пропускает пересборку бандлов. Без явных путей `git commit` заберёт весь
индекс, включая чужую параллельную работу.

**`git push`, deploy и PR — только по отдельной прямой команде владельца.**
Коммитить можно и нужно по ходу, спрашивать про коммит не надо.

**Расхождение с дизайном не чинится молча.** Всё, что меняет контракт, кадр или
приёмочный лист, ложится записью в `docs/ui/UI_V4_FINDINGS.md`: что нашли · чем
это грозит · что предлагаю · чей ход. Статус `?` ждёт дизайнера, `!` решено без
него с причиной. Закрытая запись сразу уезжает в `UI_V4_FINDINGS_HISTORY.md`.
Дефект кода, где контракт прав и однозначен, туда не пишется — он просто
чинится.

**Правки хирургические.** Меняй только строки, нужные для задачи. Не форматируй
соседний код. Prettier на CSS не запускать.

## 3. Проверки

```bash
npx vitest run --root apps/web --reporter=dot
```

```bash
pnpm ui:v4:check
```

Первое — 5774 теста, около трёх минут. Второе — оба гейта v4. Полный корневой
vitest локально не идёт: 601 файл выедает воркеры, гоняй по `--root apps/web`.

**Смоук обязателен.** Владелец не собирает руками редкие стыки: два «Позже»,
выход посреди чек-ина, очередь ack, дата на границе суток. Такие сценарии
закрываются симуляцией в vitest, а не просьбой «глянь на локалке».

Перед докладом «готово» по видимой правке собери свои бандлы и подними локалку:

```bash
pnpm bundle:legacy:auto --files=<твои файлы>
```

```bash
pnpm dev:local
```

`dev` грузит хеш-бандлы из `public/` как статику, без пересборки правку не
видно. Полный `pnpm bundle:legacy` ради превью не запускать — хеш-коллизии и
чужие бандлы.

### B. Четыре системные задачи

**Формат чисел** (`home-widgets`). Одна точка формата уже стоит —
`heys_widgets_ui_v1.js:79-85`, `NUM_GROUP_SEP` U+202F, `NUM_UNIT_SEP` U+00A0.
Остались **119 мест**, где «г» и «мг» склеены с числом прямо в строках: проза
советов `advice/_nutrition.js`, `advice/_core.js`, `day/_meal_quality.js`.
Правка клиентского текста в сотне мест.

**Часовой пояс** (`home-widgets`). Жёсткий `Europe/Moscow` снят у обоих
помощников часа. Осталось **238 мест** с `new Date().toISOString().slice(0,10)`
— это дата по UTC, до 03:00 местного она отдаёт вчерашний день. Канонический
помощник есть и верен: `heys_app_date_state_v1.js:7 getTodayISO` — время
устройства плюс правило ночи до 03:00. **Вслепую мигрировать нельзя:** часть
мест берёт UTC намеренно, под серверные ключи и журналы. Каждое место разбирать
отдельно. В задачнике заведено как `heys/3bae0f`.

**Аппаратная кнопка «назад»** (`home-widgets`). Слои Главной закрыты, приём
вынесен в `HEYS.ModalDismiss.pushHistoryLayer` (`heys_modal_dismiss_v1.js:117`),
закреплено `back-button-layers.test.js`. Не сделана вторая половина: «когда
открытых слоёв нет, кнопка уводит на предыдущую вкладку в порядке навигации».
Вкладки в историю не пишутся вовсе. Нужен порядок навигации и решение, что
считать предыдущей вкладкой — **это вопрос владельцу, не догадка**.

**Прокрутка** (`home-widgets`). Правило выполняется наоборот: строка требует,
чтобы смена вкладки ставила прокрутку в начало, а память была только у возврата
из глубины. В `heys_app_shell_v1.js:6110-6129` память заведена именно на смену
вкладки. Смена даты сбрасывает верно (`:6131-6135`). **Две зоны требуют
разного** — комментарий в коде ссылается на строку `nutrition-tab` «прокрутка».
Владелец просил эту строку пока пропустить; если возьмёшься — сначала спроси.

## 6. Что считается сделанным

Строка закрыта, когда:

- вердикт стоит `=` и факт называет адрес в коде;
- поведение закреплено тестом, если стык нельзя проверить глазами;
- `npx vitest run --root apps/web` зелёный;
- `pnpm ui:v4:check` зелёный;
- видимая правка собрана `bundle:legacy:auto` и посмотрена на `:3001`;
- всё, что меняет контракт или кадр, записано в `UI_V4_FINDINGS.md`.

Отвечай по-русски, коротко, структурой, а не сплошным текстом.
