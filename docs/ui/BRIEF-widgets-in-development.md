# Задание дизайнеру: четыре виджета Главной без вида

**Дата:** 2026-08-21 · **Экран:** Главная (виджеты) · **Канвас:**
`docs/ui/handoff-v4/canvas/Переработка дизайна приложения/design_handoff_heys_v4/home-widgets.v4.dc.html`

## Зачем это

Экран виджетов сведён с канвасом полностью: 101 строка контракта, из них 100
совпадают с кодом. Но в продукте живут ещё четыре виджета, которых **в канвасе
нет вообще**: «Инсулин», «Шаги», «Streak» и «Каскад». Они рисуются старым
дизайном с эмодзи (📈, 👟, 🔥, ⚡) и рядом с новыми плитками выглядят чужими.

Сейчас они погашены: в каталоге расстановки стоят последними, приглушены до 45
%, вместо превью подпись «в разработке», добавить нельзя; с уже собранных
экранов уходят при первой загрузке. Так и останется, пока не появится их вид в
канвасе.

Кадр `Главная · расстановка` уже показывает «Streak» и «Инсулин» именно
погашенными — значит решение согласуется с тем, что нарисовано.

## Что нужно сделать

1. Нарисовать кадры видов для четырёх виджетов в `home-widgets.v4.dc.html`.
2. Дописать в блок `[data-contract]` строки правил по каждому — в том же
   формате, что уже есть у «Тренда здоровья», «Инсулиновой волны» и «Серии».
3. Сказать, какой вид дефолтный у каждого.

После этого код снимет флаг `inDevelopment`, и виджеты вернутся в каталог.

## Что уже задано системой — менять не нужно

Эти правила действуют на все плитки Главной, они в контракте и в коде:

| Правило         | Значение                                                                                                                                    |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Сетка           | 4 колонки, ряд 64 px, зазор 8 px, паддинг 16 px                                                                                             |
| Колонка         | (ширина − 56) / 4 — на 375 px ≈ 79,8 px                                                                                                     |
| Форматы         | 1×1 (68 × 64), 2×1 (143 × 64), 2×2 (143 × 136), 3×2 (218 × 136)                                                                             |
| 1×1             | подпись, число 21 px прижато к низу, не больше одной полосы; графиков нет                                                                   |
| 2×1             | подпись и число в строку + максимум один компактный контрол                                                                                 |
| 2×2             | число ≤ 26 px + ровно один носитель состояния: полоса, спарклайн или две строки                                                             |
| 3×2             | только составные (как БЖУ тремя кольцами)                                                                                                   |
| Фон плитки      | песок `#efe3cf` — герой (ровно один на экране) · шалфей `#eaefe0` — «идёт хорошо» · бумага `#f7efe2` — остальное. Терракота фоном не бывает |
| Цвет значения   | `#a8382b` — «обрати внимание» · `#7a8a5e` — «идёт хорошо» · чернила — нейтрально                                                            |
| Нет данных      | на месте числа прочерк, подпись остаётся; полосы и графики не рисуются, ноль не подставляется                                               |
| Мало истории    | вместо графика подпись «нужно N дней»                                                                                                       |
| Лист смены вида | максимум 5 карточек, каждая в своём формате, по возрастанию формата                                                                         |
| Размер          | свойство вида: выбрал вид — получил и его формат. Отдельного переключателя размеров нет                                                     |

Классы канваса те же, что у остальных плиток: `.w` — плитка, `.k` — подпись,
`.v` — число, `.u` — единица, `.g` — сетка. Кадры помечаются `data-demo="stop"`
и `data-screen-label="<Виджет> · <Название вида>"`.

## Виджет за виджетом: какие данные реально есть

Это важно — рисовать можно только то, что продукт умеет посчитать сегодня. Если
нужен новый показатель, назовите его отдельно: это работа в данных, не в макете.

### 1. «Инсулин» (не путать с «Инсулиновой волной»)

Показывает одну текущую волну: сколько осталось до спада.

| Есть в данных  | Что это                                                                         |
| -------------- | ------------------------------------------------------------------------------- |
| `status`       | `active` · `soon` (≤ 60 мин) · `almost` (≤ 30 мин) · `lipolysis` (окно закрыто) |
| `remaining`    | минут до спада                                                                  |
| `totalWave`    | полная длина волны, минут — из неё считается доля                               |
| `lastMealTime` | время последнего приёма, «14:30»                                                |
| `phase`        | текстовая фаза                                                                  |

Отдельный вопрос к вам: **нужен ли он вообще**, когда рядом живёт «Инсулиновая
волна» с пятью видами. Если это одно и то же другими словами — честнее убрать из
продукта, чем рисовать второй раз. Решение за вами; код снимет тип, если
скажете.

### 2. «Шаги»

| Есть в данных | Что это                              |
| ------------- | ------------------------------------ |
| `steps`       | шагов за день                        |
| `goal`        | цель из профиля, по умолчанию 10 000 |
| `pct`         | процент от цели                      |

Хватает на 1×1 (число и доля) и на 2×1 (число, полоса, остаток до цели). Истории
по дням у виджета сейчас нет — спарклайн рисовать не на чем.

### 3. «Streak» (серия дней)

| Есть в данных | Что это             |
| ------------- | ------------------- |
| `current`     | дней подряд в норме |
| `max`         | рекорд              |

Контракт уже говорит про серию важное: **её нельзя красить по значению** — длина
серии это факт, а не оценка, и красная единица после срыва бьёт по тому, кто как
раз вернулся. Число всегда в чернилах.

Формат 1×1 напрашивается. Если делаете 2×1 — второй строкой может идти рекорд.

### 4. «Каскад»

| Есть в данных | Что это                         |
| ------------- | ------------------------------- |
| `events`      | события дня точками             |
| `crs`, `pct`  | накопленный показатель, 0–100 % |
| `trend`       | `up` · `flat` · `down`          |

Сейчас он занимает 4×1 — формата, которого в системе v4 нет: сетка знает 1×1,
2×1, 2×2 и 3×2. Нужно решить, во что он переезжает: 2×1 (число и стрелка) или
3×2 (лента событий), либо снимается с продукта.

## Строки контракта, которые нужно дописать

По каждому виджету — минимум три строки в блоке `[data-contract]`:

```
<виджет>            какие виды и в каком формате, какой дефолт
<виджет> · цвет     красится по значению или нет, и по какому порогу
<виджет> · нет данных   что показывает, когда данных за день нет
```

Образец, как это уже написано у соседей (можно копировать формулировку):

> **тренд здоровья** — красится по дельте за окно 14 дней: рост — шалфей,
> падение — красный, мёртвая зона ±2 пункта — чернила
>
> **серия и оценка дня** — не красятся по значению вовсе: у серии число всегда
> чернила, у оценки дня — терракота как акцент

Если решаете, что виджет снимается с продукта, — тоже строкой контракта, чтобы
это не осталось устной договорённостью.

## Как проверить себя

В репозитории стоит сторож: он помнит каждую строку контракта и её отпечаток.
Как только вы добавите или измените строку, ближайший прогон тестов скажет,
какие именно строки поехали, и разработчик их разберёт. Ничего запускать вам не
нужно — просто знайте, что молча правка не потеряется.

## Чего делать не нужно

- Не рисовать кадры «как могло бы быть» без данных: если показателя нет в
  таблице выше, он не появится на плитке.
- Не заводить новых форматов, кроме четырёх существующих.
- Не красить плитку целиком терракотой — она только для действия и текста
  «требует внимания».
- Не придумывать отдельный переключатель размеров: размер идёт вместе с видом.
