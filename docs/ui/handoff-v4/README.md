# Handoff: HEYS v4 — клиентский путь (вход + пять вкладок)

## Overview

Редизайн клиентской части приложения HEYS: экран входа (4 состояния) и пять
вкладок — Главная, Питание, Актив, Отчёты, Инсайты, плюс второй слой Инсайтов
(«Подробно») и экран разбора HEYS Score.

Работа велась двумя потоками, и это разделение обязательно сохранить при
реализации:

- **Поток A — перекраска.** Ноль изменений DOM: цвет, радиусы, тени, плотность,
  типографика, «плашки вместо рамок». Проходит через токены.
- **Поток B — структура.** Всё, что меняет разметку: перенос блоков, слияние
  карточек, новые узлы. Ставится отдельными задачами.

Каждое B-решение в макетах помечено явно (см. раздел «Поток B» ниже).

## About the Design Files

Файлы в этом пакете — **дизайн-референсы, сделанные в HTML**. Это прототипы,
показывающие задуманный вид и поведение, а не продакшн-код для копирования.
Задача — воспроизвести эти макеты в существующей среде кодовой базы (в случае
HEYS это ванильный React через `React.createElement` без JSX, в файлах
`apps/web/heys_*.js`), пользуясь её принятыми паттернами.

Разметка макетов намеренно близка к структуре существующих компонентов, но
именами классов и вложенностью с ними не совпадает: **прототип — это
спецификация значений и правил, а не исходник разметки.** Точность чисел важнее
буквального повторения DOM.

## Fidelity

**High-fidelity.** Цвета, типографика, отступы, радиусы и состояния финальные,
ниже даны точными значениями. Числа в макетах (калории, веса, проценты) —
**плейсхолдеры**: при переносе берутся из формул кода.

## Design Tokens

Система построена на **четырёх ролях**, а не на палитре по типам данных. Пока
тема меняет только значения ролей, палитр может быть сколько угодно.

| Роль                | Что означает                       | Песочная              | Песочная тёмная | Синяя     | Синяя тёмная |
| ------------------- | ---------------------------------- | --------------------- | --------------- | --------- | ------------ |
| Фон экрана          | подложка под карточками            | `#fffaf1`             | `#141210`       | `#ffffff` | `#0d1a26`    |
| Герой               | главный ответ экрана, ровно один   | `#efe3cf`             | `#2f2820`       | `#e2edf7` | `#1d3348`    |
| Нейтраль            | обычные карточки, списки           | `#f7efe2`             | `#23201b`       | `#eef3f9` | `#182a3a`    |
| «Идёт хорошо»       | выполненное, в норме               | `#eaefe0`             | `#242c20`       | `#e4efe7` | `#17302a`    |
| Действие / внимание | кнопки, акцент, «требует внимания» | `#c67139`             | `#cf8144`       | `#2e7cc0` | `#2e7cc0`    |
| Акцентный текст     | ярусы, ссылки, крупные числа       | `#8a4a20` / `#a75c2b` | `#e2a468`       | `#1d5e96` | `#8fc1e8`    |
| Шалфейный текст     | «в норме» словом и цифрой          | `#5c6a45`             | `#9fb981`       | `#1f6e4d` | `#7fd1a0`    |
| Шалфейная заливка   | полосы прогресса, точки            | `#7a8a5e`             | `#8faa6d`       | `#3e9a6b` | `#4caf7d`    |
| Мягкое внимание     | среднее состояние                  | `#d99a63`             | `#cf9257`       | `#e0a93e` | `#e0a93e`    |
| Чернила             | основной текст                     | `#201e1d`             | `#f2ede6`       | `#101826` | `#eef3f8`    |
| Вода (исключение)   | носитель состояния воды            | `#7d98a6`             | `#8fb2c2`       | `#4c8fb8` | `#6fa8c8`    |

**Вторичный текст** — `rgba(0,0,0,.55)` / `.45` / `.42` / `.38` / `.35`; на
тёмных — `rgba(242,237,230, +0.08)`, в синей тёмной —
`rgba(238,243,248, +0.08)`. **Линии и треки** — `rgba(0,0,0,.06….09)`; на тёмных
— те же альфы на светлом цвете.

**Одно цветовое исключение:** вода получает холодный тон в носителе состояния
(полоса заполнения), фон плитки при этом общий. Второй холодный тон означал бы
возврат к палитре по типу данных — этого делать нельзя.

**Категорийная палитра `--widget-*` мертва** (5 из 6 цветов имеют ноль
обращений). Оживлять не надо: 148 захардкоженных цветов в JS сводятся к ролям
выше, а не к шести категориям.

### Типографика

- Семейство: **Figtree** (400/500/600/700/800), fallback
  `system-ui, sans-serif`.
- Герой-число: `600 64px/.9`, `letter-spacing: -.045em`. Второстепенный герой —
  `600 56…60px`.
- Заголовок экрана: `700 15px/1`.
- Заголовок яруса (`.tier`): `700 10px/1`, `letter-spacing: .16em`, `uppercase`,
  цвет — акцентный текст, отступ `20px 0 10px`.
- Подпись-ключ (`.k`): `600 10.5px/1`, `letter-spacing: .04em`, вторичный текст.
- Строка списка (`.row`): `600 12.5px/1`, паддинг `13px 0`, разделитель снизу,
  `display:flex; justify-content:space-between; gap:12px`, у значения
  `flex:none`.
- Тело заметки: `500 11.5…12.5px/1.5`.
- **Все числовые значения — `font-variant-numeric: tabular-nums`.** Без этого
  столбики прыгают при обновлении.

### Радиусы и плотность

Три ступени плотности, это ключевой приём:

| Ступень          | Паддинг        | Радиус | Что                            |
| ---------------- | -------------- | ------ | ------------------------------ |
| Герой            | 26px (24–26)   | 26px   | Карточка главного числа        |
| Рядовая карточка | 16px           | 20px   | `.grp` — сгруппированный блок  |
| Список           | `2px 16px`     | 20px   | `.cd` — контейнер строк `.row` |
| Плитка виджета   | 11px           | 16px   | сетка Главной                  |
| Кнопка/пилюля    | `12…17px 20px` | 999px  | действия                       |

Ровный забор одинаковых плашек ломается **разной плотностью**, а не снятием
подложек.

### Тени

`0 1px 2px rgba(80,50,20,.09), 0 14px 40px rgba(80,50,20,.12)` — только корпус
телефона в макете. Внутри экранов теней нет: глубина строится тоном.

## Screens / Views

### 1. Вход (4 состояния)

**Назначение:** вход клиента по телефону и PIN; отдельная карточка для куратора.

**Раскладка:** экран `330×706` (в макете), фон — цвет героя, карточка
`width:100%`, паддинг `26px 20px 18px`, радиус 26, центрирована по вертикали.

Порядок внутри карточки: логотип → отступ 32 → заголовок → поле телефона →
PIN-боксы → **слот ошибки** → клавиатура → строка поддержки.

**Компоненты:**

- **Логотип** — канонический `assets/heys-logo-horizontal.svg`, инлайном (не
  `<img>`, чтобы красить по теме). Буквы берут чернила темы, «lab» — вторичный
  текст, **два плюса всегда `#52A0D8`**. В тёмной теме буквы тонкие (без
  утолщения), перекладина «E» получает обводку 1.8, иначе читается волоском.
- **Поле телефона** — фон нейтрали, радиус 16, паддинг `14px 16px`; префикс `+7`
  вторичным, номер `600 17px`, tabular-nums.
- **PIN-боксы** — 4 шт., `56×64`, радиус 16, gap 8. Активный: фон экрана +
  `inset 0 0 0 2px` акцентом. Заполненный: фон «идёт хорошо» + точка 9px
  шалфейной заливкой. Ошибка: фон `#f3e0d2` + `inset 0 0 0 2px` акцентом.
- **Слот ошибки** — блок фиксированной высоты (`padding:13px 16px`, радиус 16),
  по умолчанию `visibility:hidden`. **Не рендерить условно** — иначе он
  раздвигает контент ровно в тот момент, когда человек ошибся и целится пальцем.
- **Клавиатура** — grid 3 колонки, gap 8, клавиша `height:46px`, радиус 14, фон
  нейтрали, цифра `600 19px`; `⌫` приглушённая (фон героя, вторичный текст).
- **Служебный вход** — иконка ключа `14px`, стоит `bottom:10px; left:10px`,
  область нажатия `44×44`, цвет `rgba(0,0,0,.11)`. Текстовой строки «СЛУЖЕБНЫЙ
  ВХОД» быть не должно.
- **Статус проверки** — пилюля поверх карточки сверху: точка шалфейной
  заливкой + «Проверяем PIN».
- **Куратор** — почта, пароль, настоящая кнопка «Войти» (акцент, радиус 999),
  внизу «Вернуться ко входу клиента».

**Поведение (сохраняется из кода):**

- Кнопки «Войти» у клиента нет — вход срабатывает по заполнению четырёх цифр.
- Клавиатура своя, не системная.
- Набранная цифра видна ~1.2 s и гаснет в точку (оверлей с страховочным
  таймером).
- **Правка кода:** вариант ошибки `is-pin-error` с `position: fixed` сверху
  экрана убирается — ошибка живёт в слоте под PIN-боксами.

### 2. Главная — только виджеты

**Назначение:** экран, раскладку которого задаёт пользователь. Согласовывается
**вид плитки**, не порядок блоков.

**Сетка:** 4 колонки, `grid-auto-rows: 64px`, gap 8.

**Дефолтная раскладка нового клиента (из кода, 11 виджетов):** Калории 2×2,
Инсулиновая волна 2×2, БЖУ 3×2, Сон 1×1, Вода 1×1, Оценка дня 2×1, Тепловая
карта 2×1, Риск-радар 2×2, Тренд здоровья 2×2, Вес 2×2, Динамика веса 2×1.

**Правила плитки:**

- **1×1** — подпись `.k` и число `600 21px`, прижатое к низу. Не более одной
  полосы, и только там, где есть осмысленная цель (вода). Графика и второй
  подписи в 1×1 не бывает.
- **2×1** — подпись слева, число справа, одна строка. Плюс **один компактный
  контрол**, и только если он уже есть в коде (у «Динамики веса» это
  переключатель 7/14/30 — набором цифр, без пилюль).
- **2×2** — число (не крупнее 26px, кроме «Калорий» — 34px) плюс **один**
  носитель состояния: полоса, спарклайн или две строки расшифровки.
- **3×2** — только для составных: БЖУ тремя кольцами. Кольца — общий компонент с
  Днём и недельными отчётами, **берутся как есть**: своя форма означала бы
  расхождение с Днём или правку компонента сразу на трёх вкладках. Одно число на
  3×2 не растягиваем.
- **Герой один на экран** — плитка Калорий: фон героя, паддинг 14, число 34px.

**Режим расстановки:** взятый виджет наклоняется (`rotate(-1.8deg)`) и получает
тень `0 12px 28px rgba(80,50,20,.22)`, остальные гаснут до 50%, место вставки —
рамка `2px solid` акцентом на заливке 14%. Кружок с минусом 22px в правом
верхнем углу плитки — удаление. Внизу — каталог, отмена и повтор. Плавающих
кнопок в этом режиме нет.

**Плавающие кнопки (общие для четырёх экранов):** еда — 52px, акцент, ближе всех
к пальцу; голод, вода, мессенджер — 40px, фон экрана + тень. Порядок снизу вверх
по частоте. **Иконка голода — круг с заливкой на две трети** (метафора
«насколько полон»); подпись — «Голод и энергия». Поля `energyLevel` в хранилище
нет, но энергия — вычисляемая сущность (`low_energy_availability`,
`day_energy_target_near` в `heys_hunger_energy_status_ui_v1.js`), поэтому из
названия она не убирается.

**Пустое состояние:** «Виджетов нет» + кнопка «Добавить виджет». Новому клиенту
не показывается никогда.

### 3. Питание

Ярусы: **Сейчас** → **Дневник** → **Разбор дня**.

- **Герой** — «Осталось на сегодня», число 64px акцентным текстом, полоса
  прогресса 6px, под ней «съедено N / бюджет N».
- **Сейчас** — строка «Окно приёмов · закроется в 21:09 · через 2:14» (контейнер
  `.cd`, паддинг `14px 16px`).
- **Дневник** — контейнер `.cd`, приёмы строками: время и название `700 13px`,
  ккал справа, под ними состав вторичным `500 11.5px/1.5`. Последняя строка без
  разделителя.
- Кнопка «Добавить приём пищи» — пилюля акцентом.
- **Разбор дня** — «Суточные итоги» таблицей 5 колонок (ккал/Б/Ж/У ×
  факт/норма/отклонение), tabular-nums; клетчатка и вредность парой плиток;
  «Волны за день»; «Вода» с кнопками +200 / +500.
- **Обратные показатели:** вредность и сахар меряются долей от порога, где
  меньше — лучше, шкала инвертируется. У шкалы должно быть направление, иначе
  спор повторится на каждом обратном показателе.

### 4. Актив (пилотная вкладка)

Ярусы: **Сегодня** → **Действие** → **История**.

- **Герой** — «Цель дня», число 64px. Под ним свёрнутая строка «Затраты 2145 ·
  дефицит 10 %» с шевроном.
- **Причина уровня цели — ровно одна или её нет.** Ветки взаимоисключающие:
  рефид перекрывает долг; буст вчерашней тренировки не показывается отдельно —
  он внутри затрат. Ветки: обычный день, долг (`+478` терракотой), снижение
  (`−185` шалфеем), загрузка (цель задана планом, дефицит не показывается
  вовсе).
- **Сегодня** — шаги в карточке «идёт хорошо» (полоса 5px, метка цели), под ней
  список фактов `.cd`: бытовая активность, зарядка, голод. **Незаполненные факты
  схлопываются в одну строку** «Отметить: быт, зарядка, голод» — слот на месте,
  но старт дня не выглядит списком укоров.
- Строка «Кардио» — свёрнутый заголовок существующего блока тренировок, ведёт в
  него по тапу. Компонент с зонами пульса не заменяется.
- **История** — календарь зарядки 14×2 точками, заголовок со счётчиком серии
  «Зарядка · 6 из 14», переключатель «28 дней / Месяц», строка «Тренировки за
  месяц».
- Переключатели набраны подчёркиванием, но **область нажатия 44 pt по обеим
  осям** (`min-width:44px; min-height:44px` + компенсирующий отрицательный
  margin).

### 5. Отчёты

Ярусы: **Итог периода** → **Динамика** → **Дни**.

- **Герой** — «Баланс за неделю», `+1 435 ккал`, под ним «Съедено больше плана —
  это ≈ 186 г жира». **Коэффициент несимметричен:** профицит `ккал / 7.7`,
  дефицит раскладывается на 77 % жира, 18 % гликогена, 5 % мышц плюс вода
  (гликоген × 3) — те же 1435 в минус дают ≈ 420 г. Зеркальная подпись для
  недобора соврёт втрое.
- **Итог периода** — **плитка HEYS Score**: подпись `.k`, дельта справа
  шалфейным, число 40px акцентным текстом, спарклайн 150×44, снизу строка «Из
  чего сложился» с шевроном. Ниже пара плиток «Дней в норме» и «Средняя оценка».
- **Динамика** — график отклонений столбиками от нулевой линии (вверх недобор,
  вниз перебор), пунктир — план, подпись-легенда обязательна; ниже вес за 61
  день со спарклайном и прогнозом.
- **Сон и самочувствие** — три числа в ряд.
- **Дни** — список, где **уровень несёт точка перед датой**, а значение остаётся
  нейтральным; внизу «ещё N дней».
- **Окна блоков не подчиняются переключателю периода:** хитмап — 7 дней, вес —
  61, долг — 3 (это окно расчёта компенсации, не отображения). Переключатель
  управляет только тем, что действительно параметризуемо.

### 6. Инсайты

Ярусы: **Сделай сегодня** (герой) → **Каскад** → **Стоит внимания** → **Что
заметили** → вход в «Подробно».

- **Герой «Сделай сегодня»** — одна фраза куратора `600 15px/1.45`, под ней
  максимум три действия строками на фоне экрана, радиус 16. **Точка перед
  строкой несёт приоритет** (срочно / важно / желательно) — тот же приём, что в
  списке «Дни».
- **Каскад** (см. отдельный раздел ниже).
- **Стоит внимания** — предупреждения **голосом куратора**: не «риск срыва 58
  %», а «вы спите меньше шести часов вторую ночь, после таких дней у вас обычно
  срыв вечером». Под наблюдением — опора: «замечено на ваших данных за 18 дней».
- **Что заметили** — паттерны строками с честной зрелостью: «6 из 8 дней»,
  «нужно ещё 4 дня». Незрелый паттерн не прячется и не выдаёт себя за вывод.
- **Период** — «7 дней» активно, «30 · ещё 12» видно, но неактивно. Блокировку
  показываем честно: пользователь понимает, что вкладка появится.

**Снято в архив (не рисовать):** кольцо Trend Score с пятью категориями, риск
срыва числом, «Что если», время приёма пищи, метаболический статус, футер
«Уверенность N %», бейдж точности. Логика остаётся в коде, с экрана уходит.

### 7. Инсайты · Подробно (второй слой)

Прогноз веса → метаболические разделы строками (метаболический фенотип,
продвинутая аналитика) → итоги недели и месяца → полнота данных (18 из 30, что
уже открыто и что через сколько дней).

### 8. Разбор HEYS Score

Герой: число 56px, рядом «+40 за 2 недели», под ним — «Ритм устойчивый. Если ещё
неделю держать так же — выйдете на свой максимум». **Без «из 100»** — потолок на
практике 0.87–0.93, реальные клиенты живут на 45–70, и недостижимая цель
демотивирует. Подпись под числом — только проверяемый факт («шестая неделя
подряд без просадки»), без сравнений вроде «быстрее, чем обычно»: базы для
«обычно» нет.

**Это разложение каскада, а не сумма вкладов.** Заголовок — «Из чего сложился
каскад». Строки: Питание `+25`, Сон `+18`, Активность `+15`, Ведение `+7` —
собственные факторы движка (качество еды и штраф за перебор; отбой и
длительность; шаги, тренировки, быт; чек-ин и замеры).

**Контракт реализации: сумма строк равна Score.** 25 + 18 + 15 + 7 = 65.
Скользящее среднее линейно, поэтому вклад каждой группы факторов считается той
же формулой по её собственной доле, и сумма сходится. Тонкость: дневной вклад и
итог обрезаются потолком, поэтому доли после обрезки нужно нормировать
пропорционально — иначе сумма разъедется на пару пунктов, и человек, который
сложит, увидит нестыковку.

**Любая фраза с утверждением об истории генерируется из данных или не
показывается вовсе.** Формулировки вроде «шестая неделя без просадки» или
«быстрее, чем обычно» с макета сняты: первая на реальных данных оказалась
неверной, у второй нет базы для сравнения.

Почему именно так: 65 — это сырой CRS, он считается **только** из истории DCS
каскада. Если рядом с ним поставить слагаемые вроде веса и самочувствия, Score
перестаёт быть срезом каскада и становится новой композитной формулой — ровно
тем, от чего мы уходили, снимая Trend Score. Поэтому вес и самочувствие в
разборе не участвуют, а «дни в норме калорий» входят в строку «Питание».

**Зоны называются человеческим языком, а не игровыми терминами.** На полосе —
Начало · Набираю · Держу ритм · Максимум; под числом Score — «Ритм устойчивый».
Проверка для любой подписи: она отвечает на «как у меня дела» или на «что
дальше». Расстояние в пунктах («до пика 5») не отвечает ни на то, ни на другое —
это цена в валюте, которой человек не пользуется. Вместо неё — условие: «если
ещё неделю держать так же, выйдете на свой максимум».

## Каскад — отдельно, это самый нагруженный компонент

Каскад отвечает на два разных вопроса, и они разведены по вкладкам:

- **«Что я делаю сейчас»** — карточка в Инсайтах: точки решений, вклад дня,
  состояние словом.
- **«Куда это идёт»** — плитка HEYS Score в Отчётах: кривая за месяц.

**Карточка в Инсайтах:**

- Шапка: состояние словом («Держу ритм») слева, «растёт ↑» шалфейным справа.
  **Процента уровня быть не должно.**
- Полоса состояний: трек 8px, заливка шалфейной, три засечки (`2×14px`,
  последняя акцентом). Под полосой подписи: Начало · Набираю · Держу ритм ·
  Максимум. **Числа засечек на экран не выходят.** В макете они стоят на 25 / 45
  / 70 как плейсхолдеры. **При реализации верхняя засечка привязывается к
  персональному потолку** (он уже возвращается расчётом; у реальных клиентов
  0.87–0.93) и ставится процентов на десять ниже него — чтобы в зону можно было
  войти, а не только коснуться. Жёсткая 70 обесценит слово «Максимум» в первый
  же раз, когда кривая пойдёт выше.
- «Решения сегодня +0,4» — вклад дня отдельно от накопленного.
- **Точки решений:** ряд из ~10 точек. Размер несёт вес события (7–13px), цвет —
  знак: шалфейная заливка за то, что каскад держит, акцент за то, что рвёт,
  `rgba(0,0,0,.12)` — нейтральное. Последняя обведена `0 0 0 3px` полупрозрачным
  шалфейным. Ось подписана временем: «07:40 … сейчас».
- Нижняя строка: «За две недели +40 · смотреть в Отчётах».

**Шкала — критично.** Рисуем по **сырому CRS**, не по показываемому.
Показываемое число у клиента в плато 35 дней стоит в коридоре 80–82 при реальных
колебаниях ±16 пунктов — на нём кривая превращается в прямую. При этом **кривая
несущая, дельта — подпись**: у клиента в плато размах 23 пункта при дельте −2 за
месяц, и на дельте такой месяц выглядел бы пустым.

**Задача разработки:** сырое значение становится единственной внешней шкалой —
виджет каскада на Главной и лидерборд переводятся на неё же; показываемое
остаётся только внутренним вкладом momentum в Day Score и наружу не выходит.
Ранжирование в лидерборде не меняется: обе ветви кривой монотонны.

**Trend Score сносится насовсем** — держать две сводные оценки нельзя.

## Interactions & Behavior

- **Тач-цели:** ни одна интерактивная область не меньше 44 pt по обеим осям,
  даже если элемент набран подчёркиванием или иконкой. Достигается
  `min-width`/`min-height` плюс компенсирующий отрицательный margin — визуально
  ничего не меняется.
- **Свёртки:** «Затраты» на Активе, метаболические разделы, итоги. Свёрнутое
  **не должно считаться**: сейчас `CollapsibleSection` прячет через
  `max-height`, дети рендерятся и считают на первом кадре.
- **Раскрытия по тапу:** строка «Кардио» → блок тренировок; «Из чего сложился» →
  разбор Score; «Как считается долг» → объяснение.
- **Переключатели периода:** 7/14/30 в Отчётах, 28 дней/Месяц в Активе, 7/30 в
  Инсайтах. Выбор сохраняется.
- Анимаций сверх существующих не вводится. Единственная — оверлей PIN-цифры (1.2
  s).

## State Management

Новых состояний дизайн не заводит. Используются существующие: выбранная дата,
период отчёта, режим расстановки виджетов, состояние опроса голода, статус
синхронизации.

Гейты видимости: в Питании семь полей профиля, в Отчётах два, в Инсайтах **не
проверено**: ни одного не найдено, но сплошной проверки не было. Если гейт
найдётся, правило ниже применяется и там. **Правило:** пустое состояние рисуем
только там, где гейт по данным (пользователь закроет его сам, накопив дни). Гейт
по настройке или тарифу — раздела просто нет на экране; пустая карточка, которую
нечем заполнить, это шум.

## Поток B — что меняет разметку (отдельными задачами)

1. **Герой вынесен над ярусом** — «Цель дня», «Осталось на сегодня», «Баланс за
   неделю» стоят до заголовка яруса. Правило: герой — сама цель, ярус под ним —
   всё, что её объясняет и что за неё сделано.
2. **«Зарядка» и «Тренировки за месяц» слиты** в одну карточку истории.
3. **Порядок в «Динамике» Отчётов:** отклонение от плана перед весом.
4. **Слот ошибки PIN** фиксированной высоты; `is-pin-error` (fixed сверху)
   убирается.
5. **«Виджеты» → «Главная»**, первой позицией в меню (одна строка кода: label и
   порядок массива).
6. **Плитка HEYS Score** в «Итоге периода» Отчётов и экран разбора.
7. **Инсайты пересобираются** по разметке выше; девять разделов сводятся к трём
   на первом экране плюс второй слой.
8. Строка «Кардио» как свёрнутый заголовок существующего блока — дёшево, но всё
   же новое состояние.

## Что мешает переносу (известные дефекты кода)

- **Норма калорий в аналитике Инсайтов** считалась от жёстких 2000 через три
  вызова несуществующей `HEYS.Day.calculateOptimum` (риск срыва, энергия дня,
  метаболический стресс). Починено, коммит `544a535df`.
- **Двойной счёт дневного сна** — сообщалось, что запасной путь прибавляет
  дневной сон к `sleepHours`, который его уже содержит. **Повторной проверкой не
  подтверждено** (`heys_steps_v1.js:1388` складывает ночь и дрёму из компонентов
  времени). Пункт висит до ссылки на конкретное место — искать баг по нему пока
  не стоит.
- **Бандл Инсайтов не ленивый** — 315 КБ gzip приезжают безусловно через
  `requestIdleCallback`, платят все, включая тех, кто вкладку не открывает.
- **Свёрнутые секции считаются** на первом кадре.
- **Раскладка виджетов не уезжает в облако** — ключи layout в чёрном списке
  синхронизации. Обещать «ваш экран везде» нельзя, пока не снимут.
- **Мёртвые тумблеры:** «дни недели» и «даты» у тепловой карты, «источник» у
  риск-радара, период у «Веса» (окно всегда 14 дней). Настройку, которая ничего
  не меняет, надо либо чинить, либо убирать с глаз.
- **«Калориям» нужна ветка 2×1** — пока разрешён единственный 2×2, это не
  виджет, а зашитый герой.
- **Кольца БЖУ рисуют четыре места** (`pi_ui_rings.js`, `pi_ui_cards.js`,
  `pi_ui_dashboard.js`, `pi_ui_meal_rec_card.js`). Движок делаем один, вызовов
  остаётся четыре.
