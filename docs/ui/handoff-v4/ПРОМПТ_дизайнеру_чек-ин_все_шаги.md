# Промпт дизайнеру — утренний чек-ин: все шаги

Дата: 2026-08-16. Основание — живой код, не канвас и не старые промпты.

- План шагов: `apps/web/heys_morning_checkin_v1.js` (`getCheckinSteps`,
  `shouldShowMorningCheckin`, `buildMorningCheckinPlan`)
- Экраны: `apps/web/heys_steps_v1.js`
- Вчера: `apps/web/heys_yesterday_verify_v1.js`
- Регистрация: `apps/web/heys_profile_step_v1.js`, согласия —
  `apps/web/heys_consents_v1.js`
- Цель шагов (алгоритм уже принят):
  `docs/ui/handoff-v4/ПРОМПТ_дизайнеру_чек-ин_цель_шагов.md`

Рисовать в четырёх палитрах. Класть **поверх**
`docs/ui/handoff-v4/canvas/Регистрация и чек-ин v4.dc.html`.

Это **поток B**: можно склеивать экраны, менять ввод, прятать редкое во второй
слой. Нельзя выкидывать поле, если оно пишет в день или меняет норму / тренд /
волну.

---

## Главное в одну строку

Каждое утро человек закрывает пять обязательных значений (вес, время сна, оценка
сна, три шкалы самочувствия, цель шагов) и при необходимости разбирает вчера.
Редкое (холод, добавки, зарядка, замеры, загрузочный) не должно растягивать
ритуал на десять экранов — но и не должно исчезнуть.

Предварительный канвас уже близко. Ниже — что в коде на самом деле, что в
канвасе верно, что упрощено слишком сильно.

## Как устроен флоу (логика, не картинка)

Два разных мастера, не один.

1. **Регистрация один раз**, пока профиль неполон. Согласия отдельно и раньше:
   без них чек-ин не открывается (`HEYS._consentsValid !== true`).
2. **Дневной чек-ин каждый логический день** (граница 03:00), если обязательные
   поля дня ещё не стоят.

Показ: `shouldShowMorningCheckin`. Не показывают, если нет клиента, нет
согласий, нет доступа (trial/подписка), или обязательное уже в дне /
подтверждено куратором. Если куратор уже внёс вес/сон/настроение — мастер не
открывают: клиент видит данные в дневнике.

Сессия замораживает список шагов на открытии. Иначе вес, записанный в фоне,
выкидывает шаг из списка и «перепрыгивает» экран.

Список на сегодня собирает `getCheckinSteps`. Порядок в коде:

| id                | Обязателен?            | Когда есть                                           | Куда пишет                         |
| ----------------- | ---------------------- | ---------------------------------------------------- | ---------------------------------- |
| `yesterdayVerify` | если показался         | вчера/дыры: нет еды, 0 ккал, или съедено < 50% нормы | решение по прошлым дням            |
| `weight`          | да                     | каждый день, пока нет `weightMorning`                | день + текущий вес профиля         |
| `sleepTime`       | да                     | пока нет `sleepStart` и `sleepEnd`                   | день                               |
| `sleepQuality`    | да                     | пока нет `sleepQuality`                              | день (+ опциональная заметка)      |
| `morning_mood`    | да                     | пока нет `moodMorning`                               | день: настроение, бодрость, стресс |
| `stepsGoal`       | да, каждый день заново | пока `stepsGoalConfirmedDate` ≠ сегодня              | профиль: цель + дата               |
| `refeedDay`       | нет                    | рекомендация долга или ручной флаг                   | `isRefeedDay`                      |
| `cycle`           | нет                    | **снято с релиза**, не рисовать                      | —                                  |
| `measurements`    | нет                    | согласие на замеры и ≥ 7 дней с прошлых              | талия, бёдра, бедро, бицепс        |
| `cold_exposure`   | нет                    | в полном плане всегда, можно пропустить              | тип + время                        |
| `supplements`     | нет                    | согласие на добавки                                  | **план на сегодня**, не «выпил»    |
| `morningRoutine`  | нет                    | мотивационный финал; не держит мастер сам по себе    | копия зарядки / статус             |

Сейчас в дневном автопоказе хвост часто **отрезают** (`requiredOnly`): иначе
после записи куратором клиент видит 6+ экранов. Это защита от длины, не отмена
функций. Канвас склеивает хвост в пятый экран — это правильный ответ на ту же
проблему. Полный функционал = хвост жив, но не отдельными шагами.

Зарядка после первого приёма пищи — **не шаг чек-ина**. Это отдельный оверлей
днём. В чек-ине только утреннее напоминание.

## Что на каждом шаге сейчас в коде (антиреференс по виду)

Код перегружен эмодзи, градиентами, «ты», советами про сердце и сладкое. Вид
оттуда не копировать. Данные и состояния — да.

### 0. Вчера (`yesterdayVerify`)

Показывается, если есть дни до сегодня, которые ещё не закрыты решением.

День «дыры», если **не** подтверждён и выполняется одно из: нет приёмов, ккал ≤
0, съедено меньше половины нормы. **Шаги 0 и вода 0 сами по себе шаг не
открывают.** В канвасе это написано иначе — поправить.

Четыре закрывающих действия, разные по смыслу:

1. **Реальные данные** — ел меньше / голод, цифры верные, статистика их берёт.
2. **Дозаполнить позже** — мягкая отметка: этот чек-ин закрыт, завтра день снова
   в списке (граница 03:00).
3. **Очистить дни** — пустые, в статистику не идут.
4. **По ощущениям** — четыре силы: не доел (~78%), как надо (~110%), скорее
   переел (~155%), сильно переел (~200%). Пишет оценочные приёмы, помечает
   `estimated_fill`.

Сейчас `canSkip: false`: без выбора мастер не идёт дальше. «Пропустить» в
канвасе = по смыслу «позже», не потеря дня.

Нужны два кадра: один день и пачка. Пачка — от свежего к старому.

### 1. Вес (`weight`)

Колёса: целые кг + десятые. Предзаполнение — последний известный вес, иначе из
профиля. Пишет `day.weightMorning` и `profile.weight`. Серия и XP — по факту
записи.

Пропуска в коде **нет**. Без цифры шаг обязательный не закрывается.

Канвас предлагает «Не взвешивался» → средний вес за 3 дня с меткой «расчётный»:
норма его берёт, тренд и график — нет; нет трёх дней — вес из профиля; серия
растёт как обычно. Отметки такого дня в истории серии в этой поставке нет —
лучше без неё вовсе, чем частично. Это **новое правило**, не отрисовка. Брать:
иначе человек без весов застревает. Нарисовать и обычный ввод, и расчётный итог.

Первое утро: нет серии и нет «−0,8 кг за неделю». В коде сейчас прогноз на 2
недели — на первый слой не тащить.

### 2. Сон — в коде два экрана

`sleepTime`: колёса «лёг / встал», герой — часы сна. Дефолт — вчера или
23:00–07:00. Дневной сон утром **не спрашиваем** (отдельный шаг дневника).

`sleepQuality`: слайдер 1–10, кнопки 1/4/7/10, совет, поле заметки. Заметка
необязательна, но поле живое.

Склеивать в один экран — да. В данные по-прежнему два шага:
`sleepStart/sleepEnd` и `sleepQuality`. Заметку — второй слой («что помешало»),
не выкидывать.

Сравнение с нормой сна из профиля — можно на первом слое.

### 3. Как вы сегодня (`morning_mood`)

Уже один экран, три шкалы 1–10: настроение, **бодрость** (`wellbeingMorning`),
стресс. Стресс растёт в другую сторону. Обязательный. Предзаполнение — среднее
вчера или 5.

Канвас назвал среднюю шкалу «Самочувствие». Оставить три поля. Если
«самочувствие» читается лучше «бодрости» — можно переименовать, смысл тот же:
ресурс тела, не настроение.

Три полноэкранных героя не делать. Ползунок + слово справа — ок.

### 4. Цель шагов (`stepsGoal`)

Алгоритм и состояния уже в отдельном промпте и в канвасе. Не пересобирать. Код
шага — антиреференс: сетка кнопок, «+87 ккал», эмодзи, ты-форма.

Обязателен каждый день. Пишет `profile.stepsGoal` + `stepsGoalConfirmedDate`. Не
множитель калорий.

### 5. Хвост — в коде отдельные skip-шаги

**Холод.** Четыре типа, не да/нет: нет, холодный душ (−5% волны), ванна (−10%),
моржевание (−12%). Плюс время. Тип меняет инсулиновую волну — бинарное «Было» на
первом слое можно, тип обязателен хотя бы вторым слоем. Пустой ответ (`none`)
тоже пишется, чтобы не спрашивать снова.

**Добавки.** Это **план на день** (`supplementsPlanned` / `getPlanned`), не
галочка «выпил». Курс правится здесь («＋»), факт приёма живёт в дневнике.
Канвас с галочками «выпил» ломает смысл.

**Зарядка / рутина.** Напоминание, протокол под утренний ресурс (бережный /
средний / высокий), не отметка «сделал». «Сделал» спрашивают после первой еды.
На экране чек-ина — открыть протокол или закрыть «Готово».

**Замеры.** Талия, бёдра, бедро, бицепс, сторона лево/право. Показ раз в ≥ 7
дней и только если согласие на замеры включено. Строка «прошло N дней» — слой 1,
сами поля — слой 2 / раскрытие.

**Загрузочный день.** В канвасе нет, в коде есть. Появляется, когда система
рекомендует или человеку разрешён ручной выбор. Да/нет + короткая причина. На
пятом экране — строка, не отдельный мастер. Если рекомендации нет — строки нет.

Пустой пятый экран: «Готово» активно сразу. Пропуск хвоста не должен блокировать
утро.

## Регистрация — коротко, чтобы чек-ин стыковался

Согласия **до** любых персональных данных. Обязательные два: пользовательское
соглашение и ПДн. Дочитать до конца, подпись кодом доступа. Необязательные на
том же экране, по умолчанию выкл: замеры, добавки, напоминания, маркетинг.
`health_data` из обязательного набора изъято — не рисовать как обязательное.

Четыре шага профиля:

1. Имя (обязательно), фамилия (нет), пол, дата рождения. Цикл не спрашиваем.
2. Рост, вес (целые, в профиль как базовый), целевой вес.
3. Цель × темп + активность: снизить −10/−15/−20, удержать 0, набрать +10/+15;
   `activityLevel` = sedentary / light / active. Пока нет факта шагов, отсюда
   прогноз недель; расход дня — по факту.
4. Норма сна (4…12 шаг 0.5, ввод − / +) и инсулиновая волна: 2.5 / 3 / 4 / 4.5
   ч.

Итог регистрации — три конца: доступ открыт → «Начать утренний чек-ин»; ждём
куратора; неделя с даты. Дневной чек-ин не открывать без доступа.

Возврат: вес старше 3 суток в регистрации переспрашиваем
(`profileBodyCapturedAt`).

## Оценка предварительного канваса (непредвзято)

Брать как каркас:

- Приветствие на первом вопросе, не отдельным экраном.
- Сон время + оценка на одном экране.
- Три шкалы одним экраном.
- Вчера до точек прогресса.
- Пять точек: вес, сон, самочувствие, шаги, остальное.
- Цель шагов: одно число, одна причина, слайдер, метка совета.
- Первое утро без фальшивой динамики.
- Дневной сон утром не спрашивать.
- «На вы», без эмодзи-гирлянды.
- Хвост одним экраном вместо пяти skip-модалок.

Поправить, иначе реализация снимет функцию:

1. Вчера открывается по еде/ккал, не по «шаги 0, вода 0».
2. Три выхода вчера не покрывают четыре смысла. «Пропустить» = только «позже».
   «По ощущениям» обязано дать четыре силы. «Это правда мало ел» нельзя смешать
   с «очистить».
3. Добавки — план курса, не «выпил».
4. Холод — тип влияет на волну; «Было / не сегодня» мало.
5. Нет загрузочного дня.
6. Заметка о сне пропала.
7. В шапке канваса «четыре экрана», в точках пять — выровнять.
8. Чипы сна 6/7/8/9 режут 7.5 и 4.5 из кода.
9. «Самочувствие» ок как подпись, поле всё равно `wellbeing`.

Не спорить ради кода:

- Склейка экранов.
- Колёса веса и сна на экране.
- Нет крестика, назад с первого нет.
- «Не взвешивался» с расчётным весом — брать, нарисовать состояния.

## Слои (на каждый экран чек-ина)

Общее:
`цель — закрыть утро без потери данных; главное действие — одна кнопка вперёд; слой 1 — вопрос и ответ; слой 2 — редкое и «почему»; критическое не скрывать — обязательные пять значений и тип холода, если холод включили.`

| Экран     | Слой 1                                           | Слой 2                                                                | Не прятать                            |
| --------- | ------------------------------------------------ | --------------------------------------------------------------------- | ------------------------------------- |
| Вчера     | дырки цифрами, главное действие                  | список дней, четыре силы ощущений                                     | что день не потеряется при «позже»    |
| Вес       | число + «Дальше» / «Не взвешивался»              | как посчитан расчётный                                                | метка «расчётный», если не было весов |
| Сон       | лёг / встал / длительность / оценка              | заметка                                                               | оба времени и оценка                  |
| Шкалы     | три ползунка                                     | —                                                                     | все три значения                      |
| Шаги      | число + причина + «Готово»                       | обычная ходьба, пол 7 000                                             | план ≠ калории                        |
| Остальное | холод крупно, остальное строками, «Готово» сразу | тип холода, поля замеров, курс добавок, протокол зарядки, загрузочный | пусто = норма                         |

## Что нарисовать в этом заходе

Не регистрацию с нуля — она уже в файле. Дожать **чек-ин до полного функционала
на коротком ритуале**.

Обязательные кадры сверх того, что есть:

1. Вес: расчётный после «Не взвешивался» (есть 3 дня / нет 3 дней).
2. Сон: склеенный экран + открытая заметка.
3. Вчера: те же два кадра, но действия как в таблице выше, без «шаги/вода» как
   причины.
4. Остальное: пусто; холод «было» с выбором типа; добавки как план + «＋»;
   замеры раскрыты (4 поля); строка загрузочного.
5. Конец «Записано» — уже есть; подставить расчётный вес, если его выбрали.

Четыре палитры на основном ряде (вес, сон, шкалы, шаги, остальное). Состояния
шагов — как в том промпте, не откатывать к круглым чипам.

## Критерий готовности

По канвасу без этого файла понятно:

1. какие пять значений обязательны и что можно не трогать;
2. чем «мало ел на самом деле» отличается от «заполню позже» и от «по
   ощущениям»;
3. что пропуск веса не учит график, а норма дня не остаётся пустой;
4. что добавки утром — курс, холод — тип, зарядка — напоминание;
5. что загрузочный появляется не всегда;
6. что цель шагов не двигает утреннюю норму.

После выгрузки — тот же файл, дата в `canvas/README.md`.
