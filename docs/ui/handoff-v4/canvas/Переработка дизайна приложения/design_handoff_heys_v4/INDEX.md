# INDEX — где что лежит

**У всех восемнадцати канвасов с контрактом в шапке стоит строка сверки, и все
проверки лежат одним файлом — `contract-audit.js`** (канвас подключает его
строкой в шапке; прежде проверки жили копиями в каждом канвасе и копии
разошлись). Двенадцать проверок: кадр без строки «вид» · кнопка-пилюля мимо
общего ряда · число с единицей в прозе вне контракта · живой замер против чисел
своей строки (`data-owner`, ±1 px) · раздел контракта без строки про вид ·
объявленный замер, которого никто не мерит · ссылка на чужой канвас без строки с
этим файлом · один ключ на двух строках с разными значениями · строка «не
закрыто» без раздела «Открыто до передачи» · контракт ссылается на
`v4-canvas.css`, а канвас его не подключает · литерал на волос от роли палитры
(±2 на канал) · кадры есть, а видимых ни одного. Локальный `audit()` печатает
своё рядом, если нашёл. Пустая строка сверки — условие сборки пакета: на 28
августа она пустая у всех восемнадцати. У зоны без контракта сверка печатает
«сверка не проводилась» и зелёного ✓ не даёт — «нечего проверять» не равно
«чисто». Кадр может назвать свою строку вида явно — `data-vid`.

На каждом канвасе есть твики: `showContracts` (по умолчанию выключен — блоки
`[data-contract]` скрыты, чтобы смотреть макеты; вместо них в шапке стоит строка
«N контрактов на канвасе, M строк». Включить, чтобы читать контракт),
`allPalettes` (по умолчанию выключен — показана только песочная палитра;
включить, чтобы увидеть тёмную, синюю и сине-тёмную) `showProtocol` (по
умолчанию выключен — отвергнутые кадры скрыты, в шапке строка «N отвергнутых
кадров скрыты твиком «Протокол»») и `rules` (гасит колонки «Решения», когда
нужны только экраны). Разметка контрактов, всех палитр и заметок в файлах есть
всегда — твики только гасят её показ, `display:none` в рантайме; для чтения
контракта grep-ом ничего включать не нужно. Проверка одной строкой:
`grep -c 'data-v="' <файл>` даёт число строк контракта,
`grep -o 'data-v="[^"]*"' <файл>` — сами значения. Кому удобнее читать текстом,
а не разметкой: у тяжёлых зон рядом лежат `ACCEPTANCE-*.md` — тот же контракт
таблицей, без скрытых блоков вовсе. Пустой grep означает, что контракта правда
нет, а не что он спрятан.

## Как читать канвасы

**Сначала контракт, потом кадры.** У канваса, переложенного в новый формат, есть
блок `[data-contract]`: строки `.spec`, ключ в `<b>`, значение в атрибуте
`data-v`. Это единственный источник чисел — снимайте его целиком и пишите код и
тесты только по нему:

```js
[...document.querySelectorAll('[data-contract] .spec, .spec')].map((r) => [
  r.querySelector('b').textContent,
  r.querySelector('span[data-v]').getAttribute('data-v'),
]);
```

Числа в заметках — пересказ, при расхождении верен контракт. Длительности из
`@keyframes` брать нельзя: это демо-петли канваса. Пометки кадров:
`data-demo="loop"` — петля для показа движения, `data-demo="stop"` — стоп-кадр
(только по ним сверять геометрию, на 375 px), `data-demo="protocol"` —
отвергнутая ветка, не реализовывать. Строка `границы` говорит, что рисует канвас
и чей паддинг снаружи; строка `источник` — какой файл главный для кадра. Нет
контракта или два канваса спорят без пометки `источник` — остановитесь и
спросите дизайнера.

Образец формата — `water-add.v4.dc.html`. Контракт есть у **21** канваса: **1802
строки `data-v` всего:** `norm-correction` (46), `home-widgets` (297),
`nutrition-tab` (227), `water-add` (104), `food-meal` (87), `checkin-morning`
(83), `cycle` (79), `gamification` (78), `login` (71), `settings-system` (71),
`tips` (70), `date-remainders` (66), `registration` (63), `spinners` (60),
`questionnaire` (58), `pwa-update` (56), `curator-edits` (54),
`reports-insights` (115), `undo-bar` (49), `app-splash` (39), `product-card`
(29). Сквозных правил продукта — 25: все по шаблону «X · правило продукта»,
включая заведённые 25 августа «возврат на экран» и «прокрутка». Эти же числа
лежат в `ACCEPTANCE.md` — там они и считаются, здесь только пересказ.

**Без контракта остался один канвас, в его шапке красная плашка «МАКЕТ НЕ
СОГЛАСОВАН»:** `tab-activity`. `tab-reports` и `tab-insights` вышли из списка 29
августа — слиты в `reports-insights.v4.dc.html` с контрактом на 64 строки
(старые файлы в `history/`), `cycle` — 26 августа (79 строк), `food-add` — 28
августа, а 29-го разделён на `food-meal` (87) и `product-card` (29).

Приёмочный лист по трём тяжёлым зонам — `ACCEPTANCE.md`: по одной строке
проверки на каждый `data-v`. Отдельные листы по зонам:
`ACCEPTANCE-home-widgets.md` (297), `ACCEPTANCE-nutrition-tab.md` (227),
`ACCEPTANCE-checkin-morning.md` (83), `ACCEPTANCE-date-remainders.md` (64),
`ACCEPTANCE-cycle.md` (79 строк контракта + 25 функциональных проверок),
`ACCEPTANCE-food-meal.md` (87 строк в 15 разделах), `ACCEPTANCE-product-card.md`
(29 строк в 5 разделах) — они собраны по текущим контрактам и разбиты по
разделам.

- Файлы называются слагами (`checkin-morning.v4.dc.html`) — по ним работают glob
  и grep без кавычек. Человеческое название канваса написано в его шапке.
- Внутри канваса каждый экран телефона помечен атрибутом `data-screen-label`.
  Чтобы попасть в нужный кусок разметки, грепайте метку целиком, например
  `data-screen-label="Чек-ин · вес"`. Метки перечислены в таблицах ниже — не
  угадывайте формулировку.
- Палитровые копии экрана носят ту же метку с суффиксом: `· тёмная`, `· синяя`,
  `· сине-тёмная`. В колонке «Экранов» ниже — число уникальных меток, в скобках
  — сколько из них разных экранов без палитр.
- Справа от каждого ряда экранов стоит колонка «Решения» (`class="nt"`) — это
  объяснение, _почему_ так: границы применимости, отвергнутые альтернативы,
  поведение в краях. Числа в ней — пересказ для читаемости. Источник значений —
  только контракт (`[data-contract]`, атрибуты `data-v`): при расхождении верен
  он, и правится он. На канвасах без контракта колонка «Решения» пока остаётся
  единственной спецификацией — там сверять глазами.
- У шести канвасов нового слоя (`registration`, `checkin-morning`,
  `curator-edits`, `settings-system`, `app-splash`, `cycle`) под светлым рядом
  идут три остальные палитры. Это зеркальные копии светлого ряда, собранные
  логикой канваса из одного источника: **править только светлый ряд**. В зеркало
  не попадают колонки решений (`data-nomirror`).
- Палитры описаны переменными в `v4-canvas.css`:
  `--bg --c1 --c2 --tint --tx --ink --ac --ac2 --acs --on-acs --gr --gr2 --gr-bg --red --kb --kbk --md --edge --shadow --scrim --fade0`,
  плюс три роли линий, заведённые 25 августа: `--v4-line` (разделитель, чернила
  8 %), `--v4-track` (пустой сегмент и дорожка, 12 %), `--v4-edge` (обводка
  пилюли, 18 %). Цвета брать оттуда, а не из инлайновых стилей.
- Каждый `.dc.html` открывается двойным щелчком, но только рядом с `support.js`
  и `v4-canvas.css` из этой же папки. В `standalone/` лежат самодостаточные
  копии шести канвасов нового слоя (цикл добавлен 26 августа) — для «просто
  посмотреть», не для чтения кода.

## Одно правило — один адрес

Дубли сняты намеренно, поэтому правило ищется в одном файле:

- всё про виджеты Главной (набор, размеры, расстановка, кольца БЖУ) —
  `home-widgets.v4.dc.html`;
- всё про плавающую кнопку и быстрые действия (одна кнопка, карточка на пять
  пунктов, порядок, правка карандашом, крайние случаи «один пункт» и «ни
  одного») — `home-widgets.v4.dc.html`, раздел «Быстрые действия»; вид списка
  переключателей в настройках — `settings-system.v4.dc.html`, раздел «Чипы
  быстрых действий»;
- всё про экран входа (своя клавиатура, слот ошибки, отсутствие кнопки «Войти»,
  режим анкеты) — `login.v4.dc.html`;
- всё про строку даты и её поведение при прокрутке —
  `date-remainders.v4.dc.html`;
- всё про вкладку «Питание» (дневник приёмов, качество еды, итоги дня, приёмы

## Что не спецификация

`history/` — ранние ветки, сравнения v2 ↔ v3 ↔ v4 и снятые с производства
листы: `food-add-short` (короткий путь добавления еды: вердикта не получил, флоу
описан одним файлом `food-add`), `tab-food` (визуальный лист вкладки «Питание» —
его сменил `nutrition-tab`), `Актив - этап 4`, `Визуал v4`,
`Отчёты и Инсайты v4`, `Скелетон v4`, `HEYS - редизайн вкладок`, `HEYS Мягкий` и
его тёмная версия, `HEYS v2 - все вкладки`, сравнения v2↔v3 и v2↔v4,
`Актив v2`, `Актив - было и стало`, `Визуал v3`, `Отчёты v2`, `Питание v2`.
Правила, которые из них выжили, перенесены в актуальные канвасы; реализовывать
по `history/` нельзя.

## Порядок работы

1. Открыть нужный канвас из таблицы, найти экран по метке.
2. Прочитать колонку «Решения» рядом с этим рядом — там правила словами и
   причины.
3. Сверить с протоколом из последней колонки, если он есть: канвас показывает,
   протокол называет поля и события.
4. Расхождение канваса и кода — вопрос дизайнеру, а не повод выбрать любое из
   двух.
