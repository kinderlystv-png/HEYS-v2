внутри → чем это описано в коде.

## Как читать канвасы

- Файлы называются слагами (`checkin-morning.v4.dc.html`) — по ним работают glob
  и grep без кавычек. Человеческое название канваса написано в его шапке.
- Внутри канваса каждый экран телефона помечен атрибутом `data-screen-label`.
  Чтобы попасть в нужный кусок разметки, грепайте метку целиком, например
  `data-screen-label="Чек-ин · вес"`. Метки перечислены в таблицах ниже — не
  угадывайте формулировку.
- Справа от каждого ряда экранов стоит колонка «Решения» (`class="nt"`) — это
  спецификация словами. Если разметка и текст расходятся, прав текст.
- У четырёх канвасов нового слоя под светлым рядом идут три остальные палитры.
  Это зеркальные копии светлого ряда, собранные логикой канваса из одного
  источника: **править только светлый ряд**. В зеркало не попадают колонки
  решений (`data-nomirror`).
- Палитры описаны переменными в `v4-canvas.css`:
  `--bg --c1 --c2 --tint --tx --ink --ac --ac2 --acs --on-acs --gr --gr2 --gr-bg --red --kb --kbk --md --edge --shadow --scrim --fade0`.
  Цвета брать оттуда, а не из инлайновых стилей.
- Каждый `.dc.html` открывается двойным щелчком, но только рядом с `support.js`
  и `v4-canvas.css` из этой же папки. В `standalone/` лежат самодостаточные
  копии четырёх основных канвасов — для «просто посмотреть», не для чтения кода.

## Что не спецификация

`history/` — ранние ветки и сравнения v2 ↔ v3 ↔ v4 с русскими именами. Нужны,
чтобы понять, почему решения такие; реализовывать по ним нельзя.

## Порядок работы

1. Открыть нужный канвас из таблицы, найти экран по метке.
2. Прочитать колонку «Решения» рядом с этим рядом — там правила словами и
   причины.
3. Сверить с протоколом из последней колонки, если он есть: канвас показывает,
   протокол называет поля и события.
4. Расхождение канваса и кода — вопрос дизайнеру, а не повод выбрать любое из
   двух.
