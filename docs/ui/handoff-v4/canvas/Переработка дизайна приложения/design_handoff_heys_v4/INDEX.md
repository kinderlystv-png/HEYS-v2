# INDEX — где что лежит

На каждом канвасе есть три твика: `showContracts` (по умолчанию выключен — блоки
`[data-contract]` скрыты, чтобы смотреть макеты; вместо них в шапке стоит строка
«N контрактов на канвасе, M строк». Включить, чтобы читать контракт),
`allPalettes` (по умолчанию выключен — показана только песочная палитра;
включить, чтобы увидеть тёмную, синюю и сине-тёмную) и `rules` (гасит колонки
«Решения», когда нужны только экраны). Разметка контрактов, всех палитр и
заметок в файлах есть всегда — твики только гасят её показ; для чтения контракта
grep-ом ничего включать не нужно.

Первый файл для чтения. Ниже — карта: фича → файл канваса → как искать экран
внутри → чем это описано в коде. Пакет пересобран 23 августа 2026 (пятая
сборка): Главная стала одним экраном в 32 клетки (8 рядов) — «Вес» 2×1,
пунктирная плитка «Добавить» и строка «Изменить экран» сняты, вход в каталог —
кнопка-карандаш внизу слева, стопка плавающих кнопок свёрнута в один «+» с
карточкой быстрых действий; у «Питания» закрыта клетчатка и приведена к канону
липкость капсулы; в «Дате и остатках» нарисована ночь до 03:00, снят бар
текущего приёма и слово «Позавчера». Старые листы «все вкладки одним файлом»,
«Отчёты и Инсайты», «Скелетон», «Визуал» и «Спека» уехали в `history/`, вместо
них по канвасу на вкладку.

## Как читать канвасы

**Сначала контракт, потом кадры.** У канваса, переложенного в новый формат, есть
блок `[data-contract]`: строки `.spec`, ключ в `<b>`, значение в атрибуте
`data-v`. Это единственный источник чисел — снимайте его целиком и пишите код и
тесты только по нему:

```js
[...document.querySelectorAll('[data-contract] .spec, .spec')].map((r) => [
  r.querySelector('b').textContent,
  r.querySelector('span[data-v]').getAttribute('data-v'),
]);
```

Числа в заметках — пересказ, при расхождении верен контракт. Длительности из
`@keyframes` брать нельзя: это демо-петли канваса. Пометки кадров:
`data-demo="loop"` — петля для показа движения, `data-demo="stop"` — стоп-кадр
(только по ним сверять геометрию, на 375 px), `data-demo="protocol"` —
отвергнутая ветка, не реализовывать. Строка `границы` говорит, что рисует канвас
и чей паддинг снаружи; строка `источник` — какой файл главный для кадра. Нет
контракта или два канваса спорят без пометки `источник` — остановитесь и
спросите дизайнера.

Образец формата — `water-add.v4.dc.html`. Контракт есть у **17** канвасов, 852
строки `data-v` всего: `nutrition-tab` (187 строк), `home-widgets` (183),
`water-add` (72), `login` (42), `checkin-morning` (39), `tips` (39),
`gamification` (39), `date-remainders` (35), `spinners` (35), `registration`
(34), `pwa-update` (29), `questionnaire` (28), `settings-system` (23),
`undo-bar` (22), `curator-edits` (21), `app-splash` (16), `tab-insights` (6 —
только ярус «Питание», охват назван в контракте). Без контракта остались
`tab-activity`, `tab-reports`, `cycle`, `food-add` и `food-add-short` — числа в
них живут в прозе «Решений», сверять их приходится глазами.

Приёмочный лист по трём тяжёлым зонам — `ACCEPTANCE.md`: по одной строке
проверки на каждый `data-v`. Отдельные листы по зонам:
`ACCEPTANCE-home-widgets.md` (183), `ACCEPTANCE-nutrition-tab.md` (187),
`ACCEPTANCE-date-remainders.md` (35) — они собраны по текущим контрактам и
разбиты по разделам.

- Файлы называются слагами (`checkin-morning.v4.dc.html`) — по ним работают glob
  и grep без кавычек. Человеческое название канваса написано в его шапке.
- Внутри канваса каждый экран телефона помечен атрибутом `data-screen-label`.
  Чтобы попасть в нужный кусок разметки, грепайте метку целиком, например
  `data-screen-label="Чек-ин · вес"`. Метки перечислены в таблицах ниже — не
  угадывайте формулировку.
- Палитровые копии экрана носят ту же метку с суффиксом: `· тёмная`, `· синяя`,
  `· сине-тёмная`. В колонке «Экранов» ниже — число уникальных меток, в скобках
  — сколько из них разных экранов без палитр.
- Справа от каждого ряда экранов стоит колонка «Решения» (`class="nt"`) — это
  объяснение, _почему_ так: границы применимости, отвергнутые альтернативы,
  поведение в краях. Числа в ней — пересказ для читаемости. Источник значений —
  только контракт (`[data-contract]`, атрибуты `data-v`): при расхождении верен
  он, и правится он. На канвасах без контракта колонка «Решения» пока остаётся
  единственной спецификацией — там сверять глазами.
- У пяти канвасов нового слоя (`registration`, `checkin-morning`,
  `curator-edits`, `settings-system`, `app-splash`) под светлым рядом идут три
  остальные палитры. Это зеркальные копии светлого ряда, собранные логикой
  канваса из одного источника: **править только светлый ряд**. В зеркало не
  попадают колонки решений (`data-nomirror`).
- Палитры описаны переменными в `v4-canvas.css`:
  `--bg --c1 --c2 --tint --tx --ink --ac --ac2 --acs --on-acs --gr --gr2 --gr-bg --red --kb --kbk --md --edge --shadow --scrim --fade0`.
  Цвета брать оттуда, а не из инлайновых стилей.
- Каждый `.dc.html` открывается двойным щелчком, но только рядом с `support.js`
  и `v4-canvas.css` из этой же папки. В `standalone/` лежат самодостаточные
  копии пяти канвасов нового слоя — для «просто посмотреть», не для чтения кода.

## Одно правило — один адрес

Дубли сняты намеренно, поэтому правило ищется в одном файле:

- всё про виджеты Главной (набор, размеры, расстановка, кольца БЖУ, плавающие
  кнопки) — `home-widgets.v4.dc.html`;
- всё про экран входа (своя клавиатура, слот ошибки, отсутствие кнопки «Войти»,
  режим анкеты) — `login.v4.dc.html`;
- всё про строку даты и её поведение при прокрутке —
  `date-remainders.v4.dc.html`;
- всё про вкладку «Питание» (дневник приёмов, качество еды, итоги дня, приёмы
  полосами, голод и энергия, чипы блоков) — `nutrition-tab.v4.dc.html`;
- всё про отметки приёма добавок (три уровня отметки, курс группами времени, что
  пишется в данные) — тоже `nutrition-tab.v4.dc.html`, раздел «Добавки · отметки
  приёма»; курс и дозы заводятся в `checkin-morning.v4.dc.html`;
- карточка воды на вкладке вторична: вид, кольцо и график описаны в
  `nutrition-tab`, а все значения и пороги — в `water-add.v4.dc.html`;
- всё про отмену действия (бар, пачка, кольцо-таймер 5 с) —
  `undo-bar.v4.dc.html`;
- всё про добавление воды (анимация плитки, звук, столбик у кнопки вне Главной)
  — `water-add.v4.dc.html`;
- знак ожидания один на приложение — `spinners.v4.dc.html` (скелетонов в
  продукте нет, причина отказа записана там же);
- всё про обновление PWA (модалка, страховка, офлайн-баннер, что из мёртвого
  кода не рисуется и почему) — `pwa-update.v4.dc.html`;
- иконка приложения, подпись, цвета манифеста и стык с загрузчиком —
  `app-splash.v4.dc.html`;
- добавление приёма — отдельный флоу `food-add.v4.dc.html`, вкладка «Питание» на
  него только ссылается.

## Что не спецификация

`history/` — ранние ветки, сравнения v2 ↔ v3 ↔ v4 и снятые с производства
листы: `tab-food` (визуальный лист вкладки «Питание» — его сменил
`nutrition-tab`), `Актив - этап 4`, `Визуал v4`, `Отчёты и Инсайты v4`,
`Скелетон v4`, `HEYS - редизайн вкладок`, `HEYS Мягкий` и его тёмная версия,
`HEYS v2 - все вкладки`, сравнения v2↔v3 и v2↔v4, `Актив v2`,
`Актив - было и стало`, `Визуал v3`, `Отчёты v2`, `Питание v2`. Правила, которые
из них выжили, перенесены в актуальные канвасы; реализовывать по `history/`
нельзя.

## Порядок работы

1. Открыть нужный канвас из таблицы, найти экран по метке.
2. Прочитать колонку «Решения» рядом с этим рядом — там правила словами и
   причины.
3. Сверить с протоколом из последней колонки, если он есть: канвас показывает,
   протокол называет поля и события.
4. Расхождение канваса и кода — вопрос дизайнеру, а не повод выбрать любое из
   двух.
