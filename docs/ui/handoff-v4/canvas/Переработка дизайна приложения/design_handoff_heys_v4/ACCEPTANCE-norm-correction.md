# Лист приёмки — `norm-correction.v4.dc.html`

Переснят 3 сентября 2026 (счёт сверен с рантаймом канваса: 501 строк в DOM и в файле). Всего строк — 501, разделов — 15. Непокрытых текстовых узлов нет. Кадры зоны — 375 px.

**Границы вердиктов.** Строка «границы» задаёт предел: канвасу принадлежит только новая строка «Поправка на факт» и её состояния. Соседние строки разбора нормы — базовый обмен, дефицит, базовая цель, долг — принадлежат чужому канвасу и помечаются `—` с этой причиной, а не вердиктом.

**Три последних раздела — слепок канваса**, выведенный скриптом `contract-snapshot.js`; переснимается командой «пересними слепки», руками не правится.

Как заполнять: «Ожидание» — значение из контракта дословно. «Вердикт»: `=` совпало · `≠` расходится · `—` не в этот релиз или вне границ · `?` не измеряется.

## Пороги и окна

| Ключ | Ожидание (контракт) | Факт в коде | Вердикт |

| окно и пересчёт | окно расчёта — минимум 14 дней, рабочее 21; пересчёт раз в неделю, по понедельникам. Это разные вещи и путать их нельзя: понедельник — календарная частота события, окно — скользящие 21 день на момент пересчёта. | что показываем и когда | Решение 3 сентября (ответ на разбор кодера, кадры переснятые): ИСТЁКШАЯ ЗАМОРОЗКА НЕ СНИЖАЕТ НОРМУ САМА. Кадр «Сверка · перестройку проверить не удалось» переснят: число 2 049 помечено подписью «предложение — пока не применено», текст говорит «поправку МОЖНО применить по весу», а подвал даёт согласие — «Применить с завтра» главной, «Оставить прежнюю» вторичной, «Написать куратору» текстом. Прежний кадр показывал неприменённое изменение как результат и закрывался «Понятно», то есть после двух недель без замера норма снижалась бы без согласия — это спорило с правилом согласия из строк «решение против уведомления» и этой. Инвариант старше кадра: правится кадр. Маркер ожидания эпизодный — решение или прямой замер закрывает его, иначе старый timestamp истекал бы мгновенно при следующем застое. Было до этого решения: клиент видит результат, а не предложение: карточка изменения нормы появляется в понедельничной сверке только если изменение уже применено куратором. Иначе экран сказал бы «норму снизили», а в приложении норма прежняя. Факты недели показываются всегда |  |  |

## Self · клиент применяет сам

| Ключ | Ожидание (контракт) | Факт в коде | Вердикт |
| --- | --- | --- | --- |
| кадры Self | «Self · снижение ждёт согласия», «Self · рост применён», «Self · третий отказ подряд», «Self · отказ принят», «Pro · на согласовании» |  |  |
| решение владельца | поправка идёт в оба тарифа. Pro — решает куратор, клиент видит ту же карточку в режиме чтения («Pro · на согласовании»). Self — человек сам себе куратор: те же числа, кнопки применения у него, предохранители поднимаются в первый слой. Прежнее «только Pro» снято: вывод из нерабочей «сверки без кнопки» не в том, чтобы отнять поправку у Self, а в том, чтобы дать ему кнопку |  |  |
| решение против уведомления | делим не по «с подтверждением или без», а по тому, чьё это решение. Рост нормы система применяет сама и сообщает в тот же день, кнопка «Вернуть прежнюю норму» на карточке; снижение требует явного согласия — «Применить с завтра» против «Оставить прежнюю». Молча норма не двигается никогда, даже вверх: любое решение расчёта видно в день применения. Слова «автоматически» в клиентском тексте нет — «подняли и сказали» точнее |  |  |
