## Трек 1 · Силовая: карточка-сводка и конструктор

Инлайновый конструктор заменён на карточку-сводку плюс полноэкранную модалку.

**Ключевые решения, которые выстояли пять кругов:**

- **Единица учёта — подход.** Раунд — только группировка на экране, в схеме его
  не хранят: раунд k — это k-й рабочий подход у каждого участника связки.
- **Связка — один объект любого размера.** Суперсет, трисет и круговая
  различаются только числом участников; жёсткой двойки нет нигде. Отдых стартует
  один раз, когда закрыт круг, и равен максимуму из значений участников. Трисет
  × 3 раунда = 9 подходов.
- **Дроп — продолжение подхода.** Своего номера нет, в счётчике дня это один
  подход, килограммы идут в тоннаж полностью. Вес только вниз (−20%
  автоподстановка), максимум три ступени, таймер после последней, внутри связки
  запрещён.
- **Единица измерения — первое обязательное поле.** Килограммы и свой вес дают
  тоннаж; время и метры — свои величины отдельной строкой в итогах, а не
  пропуском.
- **Коэффициент своего веса — физический факт, не настройка.** Вопрос «на что
  похоже», не «какая доля массы тела». Без ответа упражнение не идёт в тоннаж, и
  об этом строка в итогах.
- **Группы мышц — основная плюс синергисты.** Множественный выбор из закрытого
  списка одиннадцати: основная берёт полный вес, каждый синергист половину. «Всё
  тело» убрано.
- **Перенос ≠ пропуск.** Перенос освобождает исходный день; пропуск оставляет
  день отмеченным как пропущенный.

**Программа куратора:** мезоцикл на 4 недели, сравнение план / факт, экраны
16–19.

## Трек 2 · Правка куратора после старта плана

**Правило, из которого следует всё остальное:** предложение никогда не трогает
отмеченные подходы. Поэтому «принять» безопасно всегда.

- **Отмеченный подход не меняется ничем и никогда** — ни весом, ни повторами, ни
  удалением.
- **Незакрытые подходы начатого упражнения править можно** — включая их число.
- **Начатое упражнение нельзя убрать из плана** — оно остаётся фактом, даже если
  куратор его вычеркнул.
- **Граница защиты — подход, а не упражнение.** Иначе умирает главный сценарий:
  куратор видит первый подход, понимает, что вес тяжёл, и сбавляет оставшиеся.
- **Принимается только целиком, одной кнопкой.** Разбор по упражнениям даёт
  план, которого куратор не задумывал.
- **Живое предложение всегда одно** — новое заменяет прежнее, а не встаёт в
  очередь. Отметки «прочитано» нет намеренно.
- **Молчаливого «не применилось» быть не может** — если часть правки не легла,
  об этом сказано обеим сторонам и названо упражнение.
- **Связка:** не начата — заменяется целиком; начата — состав заморожен,
  правятся только веса в незакрытых клетках. Разбирать связку правка не имеет
  права.
- **Пропущенный день:** пропущен сегодня → замена на месте, день остаётся
  пропущенным; пропущен раньше → прошедший день не воскрешают, замена приходит
  отдельной тренировкой. Отказ называется «не сегодня» и причин не спрашивает.

## Трек 3 · Отчёты, Дневник, Активность

Разбор трёх вкладок дня по схеме «было / стало». Общая находка: экраны
показывают ведомости там, где нужен вердикт.

| Турн | Экран                                 | Ход                                                                                                 |
| ---- | ------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 2    | Отчёты (`mobileSubTab === 'stats'`)   | Восемь блоков одного веса → сколько осталось, что требует внимания, остальное тихо                  |
| 1    | Сводные таблицы недель (`ReportsTab`) | 1150 px и десять спарклайнов → вердикт неделе (`1b`), либо один показатель крупно с причиной (`1c`) |
| 1    | Дневник                               | Три числовых поля оценок в каждом приёме → приём в одну строку, оценки раз в день                   |
| 1    | Активность                            | Ведомость на одиннадцать строк → одно число, ведомость по тапу                                      |

**Находка, требующая решения продукта:** настроение, самочувствие и стресс
спрашиваются в «Оценке дня» и ещё раз в каждом приёме Дневника — один и тот же
вопрос шесть раз в сутки.

## Восемь задач на схему — до кода интерфейса

1. **Тип подхода** (разминка / рабочий / дроп). Пусто = рабочий
2. **Автор и время на подходе**
3. **Программа, фазы недель и снимок плана** — под экраны 16–19
4. **Статус «пропущено» вне факта**
5. **Карточка упражнения несёт три вещи** — единицу измерения, список групп с
   пометкой основной, коэффициент своего веса. Коэффициенты в справочнике как
   данные: пополнять можно без выката
6. **Довес на подходе** — свойство подхода, а не упражнения. Индекс раунда не
   заводим
7. **Четыре поля под обещания экранов** — группа мышц, единица, вес тела в
   тоннаж, дискомфорт на подходе
8. **Владелец минут по зонам** — MET-наборов два, сверить на живых днях

Дополнительно по треку куратора: схема предложения, обновление `planSnapshot`
при принятии (прежний хранить историей), серверный guard сейчас отбивает
`skipped` наравне со `started` — под экран 15d его нужно разрешить.

## Открытые вопросы — решения владельца

**Блокируют реализацию:**

1. Распределение минут по зонам: консервативное, среднее или плотное (72–176
   ккал)
2. Два режима ввода зон — сводить или оставить
3. Правка куратора как предложение в чате: хранение, UX принятия, видимость в
   клиенте (наброски есть, нужен продуктовый вызов)

**Не блокируют, но висят:**

4. Перенос назначенной тренировки — операции нет ни в схеме, ни в коде
5. Расчётный максимум по Эпли — формулы в коде нет
6. Переходы и анимации — описаны только для перенумерации
7. Диалог двух версий подхода — до переписывания слияния
8. Дубль оценок дня и приёма (трек 3)

## Ревьюеру: на что смотреть

1. Не вернулись ли обещания, которых код не умеет
2. Есть ли экран под каждую кнопку и контрол под каждое решение
3. Сходятся ли числа между экранами одной тренировки
4. Мишени: не меньше 44 px для действий — считать и то, что свёрстано текстом
5. Не путается ли план с фактом (экраны 16–19)
6. Связка при трёх и более участниках, разминочная строка, прочерки
7. Таймер как событие, а не виджет
8. Совпадают ли ряды тем
9. Честность метрик и объёма по единицам измерения
10. Счётчики между документами — они расходились четыре круга подряд
