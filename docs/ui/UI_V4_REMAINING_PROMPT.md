## Облако vs локально — где доделывать

**«За раз до конца» — нет.** 69 `≠` + сквозные блоки A–B (push, skeleton,
haptics, breakdown) — это **много полос**, не одна сессия. Сам промпт wave 1
получил три красных теста именно от «14 полос в одном контексте».

| Где                           | Когда брать                                                                                                                       |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| **Облако (ветка `cursor/…`)** | Изолированная полоса, 1–3 коммита, свой file-scope; параллельно несколько полос **в разных файлах**; push только ветки по команде |
| **Локально (`main` / merge)** | Финальный **полный** `vitest` (CRLF на Windows); интеграция полос; merge в `main`; push/deploy по команде                         |
| **Гибрид (рекомендуется)**    | Облако — полосы B/C/D и зонные остатки параллельно; локально — блок A (сквозные правила) + merge + полный прогон                  |

**Не параллелить** двух агентов в одном файле — особенно
`ui-v4-contract-verdicts.json` (общий снимок, merge только построчно).

Облако ≠ device FS: факты git и прогонов на устройстве; push/deploy — только по
прямой команде (`CLAUDE.md` § Cowork).

### Блок B. Три сквозных дефекта (видны из нескольких зон)

Facts повторяются в `water-add`, `nutrition-tab`, `checkin-morning` — **чинить
один раз**:

1. **Пуш-уведомлений нет в `sw.js`** — ни водного, ни утреннего
   (`уведомления и точки входа` в трёх зонах).
2. **Держателя места нет нигде** — ни колец, ни чипов, ни дневника (связано с A
   `держатель места`).
3. **Отклик разошёлся с политикой**: `platform_apis:3127` даёт 8 мс вместо 10;
   двойного на удаление приёма нет — везде один `light`. Политика в
   `heys_audio_v1.js` (`HEYS.feedback.emit`).

### Блок C. Разборы плитки — 12 строк (`home-widgets`)

Листы построены; у каждой строки — **конкретный недостающий кусок** (см. факт
вердикта в JSON). Примеры:

- `разбор · Вода` — нет месячного почасового профиля и сплайна;
- `разбор · Сон` — нет оси 21:00→09:00 и подписи рисков;
- `разбор · Тренд здоровья` — нет «лучшей недели»;
- `разбор · Динамика веса` — нет подсветки плато 10+ дней;
- `разбор · Инсулиновая волна` — нет ленты семи дней.

Три строки требуют данных, которых продукт не хранит — контракт допускает лист
«за сегодня» одной строкой.

## 3. Полосы и владение

**Одна полоса — одна сессия.** Не брать четырнадцать подряд: к середине контекст
кончается, работа идёт по пересказу, а не по контракту.

**Владение по файлам, не по темам.** Два агента в одном файле — коммит, который
нельзя сделать ни с одним.

**Снимок `ui-v4-contract-verdicts.json` — общий.** Пиши только свои строки:

```bash
node scratchpad/verdicts/apply-verdict.mjs --zone <zone> --key "<key>" --verdict = --fact "file:line"
node scratchpad/verdicts/apply-verdict.mjs --zone <zone> --batch scratchpad/verdicts/<batch>.json
```

Хеши руками не трогать. После batch по зоне:
`node scripts/ui-v4-check-contract-drift.mjs --rehash <zone>`.

## 5. Проверки

- `pnpm ui:v4:check` — оба гейта зелёные до конца задачи.
- **Полный прогон в конце:** `cd apps/web && pnpm exec vitest run` (не только
  relevant pre-push). Incident 2026-08-26: relevant не поймал CRLF-стык на
  Windows — полный прогон обязателен перед merge.
- Полный прогон — **при остановленных параллельных агентах** (тесты читают
  диск).
- Стыки, таймеры, роли — vitest/jsdom, не «глянь в UI».
- Кириллицу — только `rg -i`, не `grep -i`.
- Prettier на CSS — **не запускать** (переформатирует чужие зоны).
- Legacy UI: `pnpm bundle:legacy:auto --files=<свои>` + `pnpm dev:local` для
  preview.
