# Реестр занятых файлов — раздача Cursor и Claude

Зачем файл. Cursor работает в другой программе и из сессии Claude **не виден**:
ни его файлы, ни его прогресс наблюдать нельзя. Единственная защита от
столкновения — держать здесь список того, что уже отдано, и считать эти пути
занятыми, пока владелец не скажет «закрыто». Реестр ведёт диспетчерская сессия
(«Агент-дирижёр контроля макетов»).

Правило одно: **новая задача Cursor не выдаётся, пока её файлы пересекаются с
занятой строкой этой таблицы.** Не «постараться не пересечься» — не выдаётся.

**Почему из 3 и 6 вычтен модуль занятой зоны.** Сведение зоны и есть правка её
CSS-модуля, поэтому «весь `styles/modules`» пересекается с любой работающей
сессией по построению. Один раз уже разошлось на везении: `78d6eaf22` тронул
`730-widgets-dashboard.css` через минуту после коммита в тот же файл.

**Почему из 4 вычтены `__tests__/strength-*`.** На эти тесты ссылаются вердикты
как на доказательство. Перепиши их под роли одновременно с простановкой
вердиктов — и ссылка станет неверной молча, без единого красного теста.

## Занято сессиями Claude

| сессия                                               | зона                                                                                                | состояние |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------- | --------- |
| `Спецификация текущего поведения` (`local_599885b3`) | `strength-builder` — приёмка пакета закрыта (`d624bb173`, `21177458c`); зона сведена на пятую часть | занято    |
| `Агент-дирижёр контроля макетов` (эта)               | диспетчеризация; свои правки — только по прямой просьбе владельца                                   | —         |

**Что значит «зона закрыта» у `strength-builder` — только приёмка пакета.**
Посчитано дважды, двумя сессиями независимо, числа совпали ровно: 1875 строк
канваса, `=` у 378, `?` у 1168, `≠` у 230, `—` у 99. Сведена пятая часть.
Остаток — обычные экраны продукта («История упражнения», «Подход · таблица
ввода», «Типы подходов»), а не кадры будущего: они существуют и ни разу не
сверялись.

Деления остатка на «заблокировано решением владельца» и «просто не
сведено`в реестре нет намеренно. Прикидка по шаблону имени кадра дала 460 против 708, и сессия зоны отказалась это нести: под ту же маску попали крайние случаи, никем не заблокированные, и часть чужой зоны`curator-edits`.
Число правдоподобное и потому опасное. Известны точно два очага: запись «Лента
плана» с тремя решениями за владельцем и кадр «Связка · старая, без раундов» на
16 строк.

Счёт кадров в остатке не приводится: у двух сессий вышло 165 и 108, потому что
ключ строки режется по-разному. Совпали только числа строк — их и несём.

**Зелёный дрейф не равен сведённой зоне, и путать их нельзя.** Дрейф отвечает
«отпечатки совпали», то есть «с прошлого раза не поехало». Он молчит про строки,
у которых вердикта не было никогда: у `strength-builder` дрейф зелёный и при
1168 строках без вердикта. Освобождать файлы зоны по зелёному дрейфу — значит
отдать Cursor модуль, который ещё сводят.

## Ждут сессии Claude — Cursor их взять не может

Все три про вердикты и журнал, то есть за пределами того, что отдаётся Cursor.

| что                                     | объём                                 | почему это одна задача, а не уборка                                                                                                                                                                             |
| --------------------------------------- | ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `norm-correction`: ветка «без обхватов» | 20 строк кадра NC5 + запись журнала   | кадр — ответ дизайнера на открытую запись «`?` Применённое Pro-снижение без замеров обхватов»: applied-ветка произносит «обхваты держатся», когда замеров не было. Сведение ветки и закрытие записи неразделимы |
| `checkin-morning`                       | 11 снятых вердиктов + 22 новые строки | вердикт ставит тот, кто сводил; строки переписаны пакетом от 15:18                                                                                                                                              |
| `app-splash`                            | 155 строк без вердикта                | владельца нет, см. ниже                                                                                                                                                                                         |

Долг полноты восьми «завершённых» кадров закрывается целиком первой строкой:
проверено модулем гейта — `materializeCompletedFrameEvidence` даёт 301 строку,
без `evidence` ровно 20, все в одном кадре NC5. Шесть кадров зоны
`strength-builder` не выросли; ранняя раздача «18 + REG1 + NC5» была неверной.

## Без владельца

`docs/ui/verdicts/app-splash.json` — 155 строк «Строка добавлена дизайнером,
вердикта нет», последние коммиты `c03d11a9d` и `653ad2671` не принадлежат ни
одной из работающих сессий. Пересматривает тот, кто сводил зону; владельца нет,
поэтому это отдельная задача, а не уборка по пути. Файл грязный — не трогать
никому, пока владелец не найден.

## Запрет для всех, кто не Claude-сессия зоны

`docs/ui/verdicts/**`, `docs/ui/handoff-v4/**`,
`scripts/ui-v4-check-contract-drift.mjs`, `scripts/lib/ui-v4-verdicts.mjs`.

Дополнено 3 сентября по разбору сессии `strength-builder` — дырки, которых в
первой редакции не было:

- `docs/ui/UI_V4_FINDINGS.md` и `UI_V4_FINDINGS_HISTORY.md` — это очередь
  дизайнеру и протокол закрытия; пакетная правка там опаснее правки вердиктов по
  той же причине.
- `apps/web/vitest.config.ts` — состав контуров это решение, а не правка.
- `apps/web/__tests__/**/*-canvas-{razbor,geometry,copy}.test.js` — гейты
  сведения заводятся в конце задачи по зоне.
- `scripts/ui-v4-progress-report.mjs`, `scripts/ui-v4-set-verdict*`,
  `scripts/lib/ui-v4-canvas-index.mjs` — машинерия приёмки. Вердикт ставит тот,
  кто сводил экран, и в той же задаче — это правило `CLAUDE.md`, а не удобство:
  пакетная простановка вердиктов опаснее пакетной правки кода, потому что
  неверный вердикт молча становится правдой для следующего, кто откроет снимок.
