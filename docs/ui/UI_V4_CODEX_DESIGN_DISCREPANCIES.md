# UI v4 — расхождения для проверки дизайнером

Дата начала: 2026-09-01. Владелец рабочего журнала: Codex.

Этот файл собирает только конфликты актуального канваса с подтверждённой
продуктовой, безопасностной или технической логикой. Макет остаётся источником
истины для визуального контракта, кроме случаев, где буквальное исполнение
ломает более сильный инвариант продукта.

## Как читать статусы

- `реализовано, канвас ждёт правки` — решение однозначно: код приведён к
  правильному поведению, строка остаётся именованным `≠` до обновления канваса;
- `вопрос дизайнеру` — без ответа есть несколько равно правдоподобных решений;
- `закрыто` — канвас обновлён либо повторная проверка сняла конфликт.

Для каждой записи обязательны: зона и точная строка `data-v`, что требует
канвас, что делает код, почему выбранное решение сильнее, адрес кода/теста и что
именно нужно проверить или изменить дизайнеру.

- Дизайнеру: добавить доступный выход в кадр M7 и полный текст либо явно назвать

### Strength builder — M7 не может утверждать, что отдых истёк, без таймера

- Статус: `реализовано честно, нужен отдельный canvas-state`.
- Строка `Сессия · вернулись через час · 06` и полный текст безусловно говорят,
  что таймер отдыха истёк. В production разрыв больше 45 минут достижим и без
  запущенного отдыха; редкий сохранённый таймер может также ещё идти.
- Код воспроизводит точный canvas-текст, когда сохранённый отдых действительно
  истёк. Без таймера он прямо говорит, что тот не запускался; для ещё активного
  таймера сообщает, что он продолжает идти. `Продолжить` не перезапускает и не
  подменяет состояние сессии.
- Код/тест: `apps/web/strength/heys_strength_builder_ui_v1.js`,
  `apps/web/__tests__/strength-builder-ui.test.js`.
- Дизайнеру: ограничить текущий кадр условием `expired activeRest` и добавить
  варианты без таймера/с ещё активным таймером либо утвердить общий честный
  текст.

### Strength builder — будущий план нельзя молча начать на будущей дате

- Статус: `вопрос владельцу и дизайнеру`; future preview сохранён read-only.
- Кадр `План в ленте дня` требует `Начать сейчас` на будущем назначенном дне.
  Текущий owner-контракт не определяет, куда писать факт: в будущую дату, в
  сегодня с переносом назначения либо в отдельную early-start запись.
- Реализованный default: состав и дозы видны сразу, неделя строится только из
  owner-index программы и прочитанных owner-дней, а даты переноса до ответа
  authoritative batch остаются `не загружены`. Editable Builder и старт до своей
  даты недоступны. Молчаливая запись факта в будущее сильнее повредит дневник,
  чем отсутствие CTA.
- Из-за отсутствия безопасного `Начать сейчас` единственное доступное действие
  `Перенести` становится главным. Это сознательное расхождение иерархии с
  canvas, а не доказанное совпадение.
- Canvas подписывает неделю как `мезоцикл «База»`, но схема программы не имеет
  owner-поля мезоцикла. Runtime честно показывает `program.title`, номер недели
  и место дня; выводить слово `мезоцикл` из произвольного title нельзя.
- Код/тест: `apps/web/strength/heys_strength_superset_ui_v1.js`,
  `apps/web/heys_day_trainings_v1.js`,
  `apps/web/__tests__/activity-plan-card-frame.test.js`,
  `apps/web/__tests__/program-week-overview.test.js`.
- Владельцу/дизайнеру: определить транзакционную семантику early start и
  переснять CTA; до решения не добавлять кнопку по одному тексту макета.

### Strength builder — кадр переноса склеивает четыре разных момента

- Статус: `реализовано раздельными runtime-состояниями; вопрос дизайнеру`.
- `Перенос · след в обе стороны` одновременно показывает исходную карточку до
  действия, picker, исходный след после commit и целевую карточку после commit.
  Один честный DOM не может одновременно быть до и после переноса на двух днях.
- Текущий перенос target-first и идемпотентен по `plan.transferId`; picker
  показывает только authoritative свободные даты, после commit исходный и
  целевой следы живут на своих датах. Canvas-сноска
  `Отдельного механизма переноса нет` теперь устарела: отдельная операция и след
  уже существуют. Вторая коллизия: pre-move карточка strength-canvas расходится
  с уже принятым owner-кадром Activity (`Сегодня по программе`, отдельные
  `Начать` / `Перенести` / `Пропустить`).
- Код/тест: `apps/web/heys_day_trainings_v1.js`,
  `apps/web/strength/heys_strength_superset_ui_v1.js`,
  `apps/web/__tests__/strength-plan-outcome-web.test.js`,
  `apps/web/__tests__/activity-plan-card-frame.test.js`.
- Дизайнеру: разнести composite на именованные кадры до выбора, picker, source
  trace и target trace; для общей карточки дня выбрать один owner-canvas.

### Strength builder — «день не состоялся» не имеет доменного факта

- Статус: `вопрос владельцу`; кадр не строится из одной даты.
- Прошлый `assigned` сам по себе не доказывает пропуск: допустимы поздний ввод и
  backfill. Текущий `skipped` уже является выбранным исходом, а не pending-state
  с вопросом `Что сделать с этой тренировкой?`.
- Для точного кадра нужен явный `missed-pending` либо cutoff + правило backfill,
  same-week eligibility переноса и причина для обоих исходов. Строка кадра,
  предупреждающая о попадании такого плана в калории, устарела: kernel уже
  исключает `assigned/skipped/moved`, и возвращать ложную нагрузку нельзя.
- Явный `skipped` теперь показывает спокойный исход без ретроактивного resume на
  прошлой дате и прямо объясняет нулевой тоннаж. Это не подменяет отсутствующий
  `missed-pending`: строки 01–16 кадра остаются долгом, а строка 17 фиксируется
  как `≠ logic-invariant`.
- Владельцу/дизайнеру: назвать owner факта и переходы; до этого не выводить
  decision-state по эвристике `date < today`.

### Strength builder — разминка внутри связки

- Статус: `вопрос дизайнеру`; реализацию остального flow не блокирует.
- Контракт: строки `data-v` с якорем `разминка` и кадр К5 одновременно описывают
