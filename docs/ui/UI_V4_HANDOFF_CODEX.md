| что                      | где                                                                             | кто пишет                                 |
| ------------------------ | ------------------------------------------------------------------------------- | ----------------------------------------- |

| закрытые вопросы         | `docs/ui/UI_V4_FINDINGS_HISTORY.md`                                             | туда уезжает решённое                     |
| решения владельца        | `docs/ui/UI_V4_OWNER_DECISIONS.md`                                              | владелец                                  |
| пакеты дизайнеру         | `docs/ui/UI_V4_DESIGNER_REQUEST.md`, `_2.md`                                    | отданы и отвечены                         |
| доска раздачи и журнал   | `docs/ui/UI_V4_CONDUCTOR_BOARD.md`                                              | дирижёр                                   |

`UI_V4_FINDINGS.md` ведёт один владелец не из вежливости: он дважды съедал чужую
незакоммиченную работу, когда в него писали несколько сессий.

**Словарь вердиктов — четыре значения, и они узкие:**

- `=` сошлось с контрактом;
- `≠` отступление, принято навсегда — уезжает в поимённый список исключений
  теста зоны;
- `—` к коду не сводится;
- `?` никто не смотрел.

Словарь узок, поэтому различия несут **приставки в факте**:

- `кода нет:` — реализации не существует, строить с нуля;
- `кода нет, но рядом есть:` плюс адрес — механика живёт под другим именем;
- `снято дизайнером:` при вердикте `—` — ветка отвергнута, строить **не надо**.
  Без приставки такая строка прочтётся как задание, и построят отменённое.

## 2. Чем проверять и чего проверка не видит

```bash
pnpm ui:v4:check
```

Семь гейтов. У каждого названы слепые зоны — это часть контракта проверки, а не
оговорка:

| гейт                              | сторожит                                         | не видит                                                                                  |
| --------------------------------- | ------------------------------------------------ | ----------------------------------------------------------------------------------------- |
| `ui-v4-check-undefined-roles`     | роли, не объявленные в наборах                   | не ту роль, объявленную верно                                                             |
| `ui-check-undeclared-vars`        | переменные без объявления                        |                                                                                           |
| `ui-v4-check-foreign-fallbacks`   | запасные значения мимо набора                    |                                                                                           |
| `ui-v4-check-css-test-guards`     | сторожа с `[\s\S]*?` внутри правила              |                                                                                           |
| `ui-v4-check-bare-color-literals` | голые литералы цвета                             | 26 модулей вне охвата: у них ноль означает «не смотрели»                                  |
| `ui-v4-check-contract-drift`      | изменённые, новые и исчезнувшие строки контракта |                                                                                           |
| `ui-v4-check-verdict-addresses`   | протухшие адреса в доказательствах               | 2994 сокращения вида `ui:2513`; 307 многоадресных записей; **сторожит адрес, а не смысл** |

Отдельно, вне `ui:v4:check`:

- `scripts/ui-v4-list-inherited-paint.mjs` — места, где цвет унаследован
  (`currentColor`, `inherit`), а не назван;
- `scripts/ui-v4-fix-verdict-addresses.mjs` — чинилка адресов, правит **только
  однозначное**;
- `apps/web/scripts/ui-v4-visual-capture.mjs` — замер вычисленных значений на
  живом дереве.

**`--rehash <зона>` — только после пересмотра вердиктов.** Пересъёмка отпечатков
по непересмотренным строкам сводит новый текст со старым вердиктом: гейт
зеленеет, ничего не проверив. Зона в середине переноса **должна** стоять
красной.

## 4. Очередь работы

### 4.1. Главная — 809 строк, порядок задан

Записка с граблями: `docs/implementation/HOME_WIDGETS_V4_CANVAS_ALIGNMENT.md`.
Порядок предложен той, кто зону сводила, и он обратный интуитивному:

1. **20 осиротевших вердиктов и 2 новых** — пока они висят, непонятно, какие

2. **правило заливочных ролей** — мест немного, каждое настоящий дефект

3. **правило 56 %** последним — 669 подписей, самое массовое и механическое:

Правила выписаны из канваса дословно вместе с обоснованиями — читать
первоисточник, не пересказ.

### 4.2. Полоса цели — правило получено, кода нет

Два состояния, порог **67 %**: ниже двух третей нормы `--ovl`, от 67 % `--gr2`,
дорожка `--v4-track`. Литерала `#201e1d` быть не должно.

**Пороги числа и полосы разные намеренно:** число зеленеет от 100 % («норма
закрыта»), полоса от 67 % («успеваешь к ней»). Зелёная полоса при 69 % рядом с
чернильным числом — замысел, не расхождение.

**Сужение:** порог только у плитки цели, где полоса показывает долю дневной
нормы. Полосы разбора, «по приёмам» и «Тренда здоровья» показывают вклад — один
`--gr2` без порога.

#### Три дефекта ядра экрана, найденные при разборе

Каждый проверен двумя признаками разной природы — по имени и по поведению.

1. **Кольцо отдыха закрывает список целиком.**
   `.sb-rest { position:absolute; inset:0 }` с непрозрачной заливкой
   (`750-strength-builder.css:631-641`), тогда как кадр решает обратное: «пока
   идёт отдых, упражнения видны и правятся». Правило нарушено **раскладкой, а не
   оформлением**. Переопределения нет — `.sb-rest` объявлен ровно один раз.
2. **В связке отдых не запускается вовсе.** Условие
   `patch.done && … && !groupByIndex[exIdx]` (`builder_ui:134-136`) исключает
   сгруппированные, а кадр именно про связку («Отдых · связка A», «Следующий
   раунд · A1»). Единственный вызов `setRest` — строка 135, единственное
   использование `RestRing` — строка 464.
3. **Сессии как объекта со временем не существует.** Длительность везде «сейчас
   минус начало» (`builder_ui:79`, `superset_ui:568`, `finish_ui:98`), отметки
   времени у подхода нет: `lastMark`, `finishedAt`, `endedAt`, `closedAt`,
   `updatedAt` — ноль в ядре и во всех модулях; `localStorage`,
   `sessionStorage`, `visibilitychange` в `strength/` — ноль. Отсюда оба «нет» и
   половина третьего кадра, и отсюда же расходится именованное правило
   «длительность — от первой отметки до последней».

Плюс два мелких против названных решений канваса: в интерфейсе написано «RPE»
(`superset_ui:476`), хотя канвас говорит «„RPE" в интерфейсе не пишем»; закрытые
подходы остаются полями ввода, а не текстом (`superset_ui:317-339`), хотя кадр
решает «заполненные показывают значения текстом».

## 5. Грабли, каждая проверена на себе

Полные формулировки — в `AGENTS.md`, раздел про сведение экрана с канвасом.
Здесь короткий список, чтобы знать, что искать:

1. **Зелёная проверка обязана отличать «сошлось» от «не смотрели».** Гейт,
   молчащий на неизвестном объекте, подтверждает собственную слепоту.
2. **Два способа — это два признака, а не два прогона одного.** Проверить
   исходник и бандл по одному имени — один способ, применённый дважды.
3. **Шаблон поиска — один способ.** `rg` по `apps/web/*.js` не заходит в
   подкаталоги; так две сессии подряд «не нашли» 5690 строк.
4. **Ищи по имени сущности, а не по фразе из кадра.** Одна сессия за час дала
   три ложных «нет» на восьми кадрах — 37 %, все три от поиска по формулировке.
5. **Число для человека пересчитывает другой своим кодом.** Не перечитывает —
   пересчитывает.
6. **Пакетная простановка вердиктов опаснее пакетной правки кода**: код упадёт,
   вердикт молча станет правдой.
7. **Литерал выводит место из-под охраны.** Сверка с кадром отвечает «совпадает
   ли с кадром», а не «работает ли во всех наборах»; у кадра набор один.
8. **Строка контракта дописывается в конец, а не переписывается.** Начало может
   говорить обратное решению в хвосте.
9. **Проверяй не правило, а все его места вызова.** Правило бывает верным и
   применяться по-разному.
10. **Находку, которая уходит другому, проверяй на отмену**, а не на
    подтверждение.

По главной кнопке приёма слово дизайнера дано: **остаётся песочной намеренно,

## 7. Приём, который стоит забрать в работу

Дизайнер отдельно просил сделать это правилом сборки, и не зря: **сверить список
сущностей кода со списком меток кадров**.

Все обычные проверки идут от кадра к коду и потому видят только то, что
нарисовано. Этот идёт обратно — от того, что открывается, к тому, описано ли
оно. Механика: `rg` по `className: '…modal|sheet|overlay|fullscreen|screen'`
даёт список корней, из них отбираются клиентские, и по копии каждого ищется
совпадение в канвасах.

Так нашлись экран платежа, история достижения, «Расчёт волны» и лист периодов —
живые экраны, которых не описывает ни один кадр. Ни одна сверка их не видела,
потому что сверять было не с чем.

Ход не шумит: из 13 клиентских кандидатов совпало 9.
