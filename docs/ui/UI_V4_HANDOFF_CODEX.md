## 1. Где источники правды

| что                      | где                                                                             | кто пишет                                 |
| ------------------------ | ------------------------------------------------------------------------------- | ----------------------------------------- |
| контракт экрана          | `docs/ui/handoff-v4/canvas/…/design_handoff_heys_v4/*.dc.html`, строки `data-v` | дизайнер                                  |
| вердикт по каждой строке | `docs/ui/verdicts/<зона>.json`                                                  | тот, кто сводит зону                      |
| открытые вопросы         | `docs/ui/UI_V4_FINDINGS.md`                                                     | **один владелец**, остальные шлют текстом |
| закрытые вопросы         | `docs/ui/UI_V4_FINDINGS_HISTORY.md`                                             | туда уезжает решённое                     |
| решения владельца        | `docs/ui/UI_V4_OWNER_DECISIONS.md`                                              | владелец                                  |
| пакеты дизайнеру         | `docs/ui/UI_V4_DESIGNER_REQUEST.md`, `_2.md`                                    | отданы и отвечены                         |
| доска раздачи и журнал   | `docs/ui/UI_V4_CONDUCTOR_BOARD.md`                                              | дирижёр                                   |

`UI_V4_FINDINGS.md` ведёт один владелец не из вежливости: он дважды съедал чужую
незакоммиченную работу, когда в него писали несколько сессий.

**Словарь вердиктов — четыре значения, и они узкие:**

- `=` сошлось с контрактом;
- `≠` отступление, принято навсегда: требует `reasonCode` и разрешимый
  `decisionRef`, затем уезжает в поимённый список исключений теста зоны;
- `—` к коду не сводится: требует `naKind` (`handoff`, `foreign-zone`,
  `demo-only`, `designer-removed`);
- `?` сравнение не завершено либо доказательства недостаточны. Частично
  просмотренная строка тоже остаётся `?`, пока не установлен её полный verdict.

Фразы `не подтверждено`, `не проверено`, `нужен review` и
`точное совпадение не заявляется` не являются причиной для `≠`: они прямо
описывают `?`.

Исправимое расхождение тоже остаётся `?` до правки кода. Отсутствующий
обязательный flow нельзя скрыть под `—`. Legacy-строки мигрируют по
identity-level baseline, который может только уменьшаться; закрытая зона ставит
`verdictSchema: "typed-v1"` и обязана иметь ноль legacy-строк.

Словарь узок, поэтому различия несут **приставки в факте**:

- `кода нет:` — реализации не существует, строить с нуля;
- `кода нет, но рядом есть:` плюс адрес — механика живёт под другим именем;
- `снято дизайнером:` при вердикте `—` — ветка отвергнута, строить **не надо**.
  Без приставки такая строка прочтётся как задание, и построят отменённое.

## 2. Чем проверять и чего проверка не видит

```bash
pnpm ui:v4:check
```

Гейты независимы. У каждого названы слепые зоны — это часть контракта проверки,
а не оговорка:

| гейт                              | сторожит                                                                     | не видит                                                                                  |
| --------------------------------- | ---------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `ui-v4-check-undefined-roles`     | роли, не объявленные в наборах                                               | не ту роль, объявленную верно                                                             |
| `ui-check-undeclared-vars`        | переменные без объявления                                                    |                                                                                           |
| `ui-v4-check-foreign-fallbacks`   | запасные значения мимо набора                                                |                                                                                           |
| `ui-v4-check-css-test-guards`     | сторожа с `[\s\S]*?` внутри правила                                          |                                                                                           |
| `ui-v4-check-bare-color-literals` | голые литералы цвета                                                         | 26 модулей вне охвата: у них ноль означает «не смотрели»                                  |
| `ui-v4-check-contract-drift`      | изменённые, новые и исчезнувшие строки контракта                             |                                                                                           |
| `ui-v4-check-verdict-semantics`   | typed-схему, legacy-ratchet, неизвестность как `≠`, обязательный код как `—` | истинность самого продуктового решения по ссылке                                          |
| `ui-v4-check-verdict-addresses`   | протухшие адреса в доказательствах                                           | 2994 сокращения вида `ui:2513`; 307 многоадресных записей; **сторожит адрес, а не смысл** |

Отдельно, вне `ui:v4:check`:

- `scripts/ui-v4-list-inherited-paint.mjs` — места, где цвет унаследован
  (`currentColor`, `inherit`), а не назван;
- `scripts/ui-v4-fix-verdict-addresses.mjs` — чинилка адресов, правит **только
  однозначное**;
- `apps/web/scripts/ui-v4-visual-capture.mjs` — замер вычисленных значений на
  живом дереве.

**`--rehash <зона>` — только после пересмотра вердиктов.** Пересъёмка отпечатков
по непересмотренным строкам сводит новый текст со старым вердиктом: гейт
зеленеет, ничего не проверив. Зона в середине переноса **должна** стоять
красной.

### 4.1. Первое: честный остаток `?` после двух волн

Основной остаток — `strength-builder`: 1812 строк, из них 211 `=`, 229 `≠`, 98
`—`, а 1274 ещё требуют проверки или исправления. В `norm-correction`
дополнительно осталось 149 честных `?`: прежние основания описывали
исправимые/непроверенные расхождения, а не вечные исключения.

В `reports-insights` после встречного аудита 69 строк были возвращены в `?`.
`Каскад`, inline `Что если` и непротиворечивая часть прогноза веса теперь
реализованы и проверены; в зоне осталось 38 строк долга, включая внутренние
конфликты canvas по композиции прогноза, координатам sample, чипам и числу
сценариев.

В `food-meal` тем же правилом возвращены 128 строк: 81 строка листа
копирования/переноса и ещё 47 исправимых visual-расхождений значков, кривых и
общей шапки. После source/CSS, транзакционных тестов и шести runtime captures 77
строк трёх transfer-кадров уже закрыты `=`; в зоне остаётся 51 честный `?`.

Работать есть по чему: **все 63 кадра имеют статус и адрес в коде** — шесть
разборов лежат в `docs/implementation/` и `docs/ui/designer-answers/`. То есть
известно, что реализовано, что частично и чего нет; неизвестно построчное
соответствие чисел.

Порядок: брать кадр, у которого статус «реализовано», и сверять каждую строку
независимо. Сам статус кадра не даёт права ни на один вердикт. Исправимый gap
остаётся `?`; `≠` требует typed-причину и ссылку на решение; `—` требует
`naKind` и не может скрывать отсутствующий обязательный flow.

Б1 `Конструктор · пусто` закрыт по 14 отдельным строкам: динамическая иерархия
реального назначенного плана, ручная сборка и повтор последней сессии. Кадр
теперь достижим канонически: назначение хранится в `planSnapshot`, live-журнал
до выбора пуст, а переход в факт подтверждается владельцем дня. Будущий состав
не открывает редактируемый builder. Четыре строки остаются долгом из-за
противоречия canvas, отсутствующего template flow и незафиксированного в строке
обязательного выхода fullscreen.

M7 `Сессия · вернулись через час` разобран по актуальному 15-строчному HTML, а
не по отставшему 16-строчному acceptance-снимку. Тринадцать строк закрыты `=`
после независимого source/CSS review. Строки шапки, безусловного текста отдыха и
полного текста стали typed `≠ logic-invariant`: fullscreen сохраняет доступный
`✕`, а runtime не утверждает, что отдых истёк, когда таймера не было или он ещё
идёт. После 45:00 журнал остаётся редактируемым; с 45:01 до выбора список,
статистика, меню и dock не рендерятся. `Продолжить` не пишет данные, `Завершить`
фиксирует `lastMarkAt` и длительность first→last.

**Не ставить вердикты пачкой.** Правило проекта: неверный код падает, неверный
вердикт молча становится правдой для всех, кто откроет снимок следующим.

### 4.2. Второе: три дефекта ядра экрана, найденные при разборе

Не расхождения с кадром, а работающий не так код:

типизированным отступлением. После этого геометрия применённого Pro-снижения
закрыта по двум строкам факта и иерархии кнопок: четыре строки переведены из `?`
в `=`. Проза и полный текст возвращены в `?`, потому что без замеров обхватов
код не выдумывает их стабильность. Внешний отступ карточки также остаётся `?`,
пока не сведена общая weekly-шапка; в зоне осталось 149 строк долга.

### 4.5. Что ждёт не нас

Два гейта **намеренно красные**, и это внешние ограничения пакета:

- **78 живых экранов без точного кадра** — полный машинный реестр с причиной на
  каждый в `docs/ui/UI_V4_SCREEN_COVERAGE.json`. Дизайнеру рисовать или явно
  снимать;
- **десять одинаковых имён кадров в `tips`** — пока они не уникальны, доказать
  принадлежность evidence нельзя.

Плюс открытые вопросы: `UI_V4_DESIGNER_OPEN.md` (30 дизайнеру),
`UI_V4_CODEX_DESIGN_DISCREPANCIES.md` (конфликты логики и макета), шесть решений
владельца в `UI_V4_FINDINGS.md`.

## 5. Грабли, каждая проверена на себе

Полные формулировки — в `AGENTS.md`, раздел про сведение экрана с канвасом.
Здесь короткий список, чтобы знать, что искать:

1. **Зелёная проверка обязана отличать «сошлось» от «не смотрели».** Гейт,
   молчащий на неизвестном объекте, подтверждает собственную слепоту.
2. **Два способа — это два признака, а не два прогона одного.** Проверить
   исходник и бандл по одному имени — один способ, применённый дважды.
3. **Шаблон поиска — один способ.** `rg` по `apps/web/*.js` не заходит в
   подкаталоги; так две сессии подряд «не нашли» 5690 строк.
4. **Ищи по имени сущности, а не по фразе из кадра.** Одна сессия за час дала
   три ложных «нет» на восьми кадрах — 37 %, все три от поиска по формулировке.
5. **Число для человека пересчитывает другой своим кодом.** Не перечитывает —
   пересчитывает.
6. **Пакетная простановка вердиктов опаснее пакетной правки кода**: код упадёт,
   вердикт молча станет правдой.
7. **Литерал выводит место из-под охраны.** Сверка с кадром отвечает «совпадает
   ли с кадром», а не «работает ли во всех наборах»; у кадра набор один.
8. **Строка контракта дописывается в конец, а не переписывается.** Начало может
   говорить обратное решению в хвосте.
9. **Проверяй не правило, а все его места вызова.** Правило бывает верным и
   применяться по-разному.
10. **Находку, которая уходит другому, проверяй на отмену**, а не на
    подтверждение.

## 7. Приём, который стоит забрать в работу

Дизайнер отдельно просил сделать это правилом сборки, и не зря: **сверить список
сущностей кода со списком меток кадров**.

Все обычные проверки идут от кадра к коду и потому видят только то, что
нарисовано. Этот идёт обратно — от того, что открывается, к тому, описано ли
оно. Механика: `rg` по `className: '…modal|sheet|overlay|fullscreen|screen'`
даёт список корней, из них отбираются клиентские, и по копии каждого ищется
совпадение в канвасах.

Так нашлись экран платежа, история достижения, «Расчёт волны» и лист периодов —
живые экраны, которых не описывает ни один кадр. Ни одна сверка их не видела,
потому что сверять было не с чем.

Ход не шумит: из 13 клиентских кандидатов совпало 9.
