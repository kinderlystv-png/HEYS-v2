# Протокол реализации GenDA

## Границы

- Новый код живёт только в `apps/genda-tests/`.
- Единственный источник данных —
  `Банк_врачебных_тестов_офтальмология_КАНОН.json` из каталога Doctor; DOCX и
  сайт являются производными артефактами.
- Нет импортов из `apps/web`, `apps/landing`, HEYS API или storage-контрактов.
- Production target обязан быть отдельным от `heys-app` и `heys-static`.

## Этапы и доказательства

1. Нормализация: детерминированная сборка `src/data/question-bank.json`.
2. Fail-closed валидация: 2×100, 199 оцениваемых, один unavailable.
3. UI: обучение, контрольная, результат, локальное восстановление.
4. Проверка: unit-тесты, isolated build, mobile/desktop browser smoke.
5. Публикация: отдельный origin, HTTPS, cache/security headers, rollback.

## UI-гейт

Цель — быстро выбрать тест и режим; главное действие — «Начать тест»; слой 1 —
вопрос, варианты, прогресс и навигация; слой 2 — переход по номерам, пояснение и
источники; недоступный вопрос и ограничения уверенности не скрываются.
